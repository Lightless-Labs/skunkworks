Encoding: encode arbitrary bytes using consecutive 6-bit groups, most significant bits first. The Standard alphabet in index order is ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/. Unused bits in the final sextet are zero. Empty input encodes to the empty string. Decoding returns arbitrary bytes, not necessarily UTF-8.
Always produce '=' padding to a multiple of four characters. A final one-byte group uses two alphabet symbols followed by '=='; a two-byte group uses three symbols followed by '='. Decoding requires complete four-symbol groups, including this padding. Do NOT reject non-zero unused bits in a padded final group: e.g. 'Zh==' decodes to b'f' and 'Zm9=' decodes to b'fo'.
No whitespace is ignored. All non-alphabet bytes other than legal '=' padding are rejected, including whitespace and non-ASCII UTF-8 bytes. Empty input succeeds with no bytes.

Process input bytes from left to right, skipping permitted whitespace first. Apply these rules in the stated order to the remaining bytes:
1. Once a complete padded quartet has been accepted, any further byte is InvalidPadding. Even an otherwise invalid character or an extra '=' takes this error.
2. '=' is InvalidPadding at quartet positions 0 or 1 (positions are zero-based); At position 2 it begins '=='; at position 3 it completes either 'xxx=' or 'xx=='.
3. After '=' at position 2, the next nonignored byte must be '='. Any other byte, even a byte outside the alphabet, is InvalidPadding.
4. Otherwise a byte outside the selected alphabet is InvalidByte.
A complete valid quartet yields its decoded bytes immediately. Padding ends the data, so it cannot occur in an interior quartet. At EOF, any incomplete quartet is InvalidLength. This includes an incomplete 'xx=' group: it is InvalidLength, not InvalidPadding. Validation follows byte order: an encountered error is reported before EOF length validation. One-shot decode returns Err without any partial result on error.
