1. **R2–R6:** Validate configuration first; `aging_ms=0` is valid. Then validate each job completely in input order using R3’s exact error precedence. IDs/tags use byte lengths and only ASCII lowercase letters, digits, or hyphens; hyphen-only strings are valid. All stated bounds are inclusive; `failures` accepts every `u8`.

2. **R7–R8:** Finish all local validation before checking dependencies. Scan dependencies in job/list order, checking duplicate before missing at each entry; an earlier missing entry wins over a later duplicate. Forward references are valid, dependency spellings receive no syntax check, and cycle detection—including self-edges—comes last. Empty input is valid.

3. **R1, R9–R12, R44:** Construction starts nothing. Initial snapshots have release time and attempt zero; status is an owned snapshot and exact unknown IDs return `Unknown` without mutation. Reject reversed horizons before checking the upper bound; every error is atomic, and every successful run records its horizon.

4. **R12–R13, R35–R36:** The first `run(0)` processes time zero; subsequent equal-horizon calls return nothing. Process events through `until` inclusively, including starts at that endpoint. Advance only to future Waiting ready times or completions—even if a ready-time event’s job cannot run. Aging and arbitrary run boundaries create no scheduling phase; split traces must match an unsplit run.

5. **R13–R14, R19–R20, R34:** At each timestamp, process all completions by ascending ASCII ID, each with its immediate retry line; then compute the entire transitive blocking closure and emit skips globally sorted by ASCII ID; only then schedule. All completing jobs release resources and cannot be victims.

6. **R15–R18, R43:** Attempt `A` succeeds exactly when `A > failures`; otherwise it fails. A failed final allowed attempt becomes terminal; an earlier failure retries at `T + min(retry_cap, retry_base × 2^(A−1))`. Compute mathematically without overflow. Retry lines report the failed attempt number, and internal ready/finish times may exceed the public horizon limit.

7. **R19–R21, R37, R41:** Only Waiting jobs become Blocked through Failed/Blocked dependencies, transitively; emit no skip for the failed job itself or a retryable failure. Only ready Waiting jobs whose dependencies all Succeeded compete or preempt. Running/Succeeded jobs are untouched by propagation, and all terminal states persist.

8. **R22–R24, R40:** Compute effective priority without overflowing before capping at nine; zero aging disables it. Age initial waits from release, retries from retry readiness, and suspensions from latest preemption. Rank candidates by descending effective priority then permanent input order; continue past candidates unable to start.

9. **R25–R27, R42:** Start without preemption whenever both slot and tag are free. Otherwise exactly one removal must free both resources: tag contention can require eviction despite spare capacity, and evicting a different-tag runner cannot resolve an occupied tag. Require candidate **base** priority ≥ victim base priority + 2, using nonoverflowing arithmetic.

10. **R28, R33, R40:** Rank only valid victims by lowest base priority, newest segment start/resume time, then greatest ASCII ID. After every start or preemption, recompute candidate selection at the same timestamp; a just-started job may immediately be preempted. Candidate ties never use ID ordering.

11. **R29–R32, R43–R44:** Emit preempt before start. Suspend with `ready_at=T`, unchanged attempt, and remaining duration `old_finish_at−T`; resumption preserves that attempt and remaining work. Initial/retry starts increment attempts and use full duration. Waiting snapshots count attempts already started; Running snapshots expose the current segment’s finish time.

12. **R15, R17, R20, R29, R32, R38–R39:** Match every event template exactly, including lowercase keywords and retry/start field meanings. Use unsigned decimal without leading zeros, single ASCII spaces, and no trailing whitespace/newline per element. Return only newly processed events; emit no idle, resource-wait, boundary, or other extra lines.
