1. **R1–R3, R12, R21, R36, R46:** Preserve every specified public type, field, function signature, and derive; use one Rust 2024 source file, std only, without inner attributes/comments. `Range` representation is implementation-chosen. Structural `Version` equality includes build; precedence ignores it. Range error offsets are absolute bytes, nested version error offsets operand-relative.

2. **R3–R6, R9:** Parse core fields sequentially using maximal ASCII digit runs. At each field, leading zero beats overflow, and both beat a bad following separator; accept `u64::MAX`. Missing digits yield `MissingCore` only at end, `.`, `-`, or `+`; other bytes yield `InvalidChar`. After major/minor, end or suffix markers mean `MissingCore`; after patch, a dot is invalid. No trimming, signs, Unicode, prefixes, or omitted fields.

3. **R7–R9, R19–R20:** Validate each identifier’s characters before its numeric leading-zero rule, but finish earlier identifiers and pre before later identifiers/build. Empty identifiers report their start, including a terminating `+` immediately after `-` or a pre dot. Pre numeric identifiers never overflow; build allows numeric leading zeros. Hyphens are ordinary identifier content. Preserve spelling, case, order, and absent suffixes as empty vectors.

4. **R10–R11, R14, R34–R35, R55:** Compare core numerically, then pre: release wins; numeric identifiers precede nonnumeric and compare by length then bytes; nonnumeric compares case-sensitive ASCII; equal identifier prefixes favor the shorter list. Equality comparators ignore build. Extrema must validate every candidate in input order before returning any result, including nonmatches; return the original earliest input string on precedence ties. Empty/no-match inputs yield `None`.

5. **R13–R16, R22–R23, R27, R33:** Only ASCII space/tab/CR/LF delimit tokens; whitespace-only gives `Empty { at: 0 }`. Only standalone `||` separates arms. Leading/consecutive separators report `Empty` at that separator; trailing separators report input length including whitespace. Earlier malformed arms win. Explicit comparators take the longest operator prefix and require an immediately attached digit-starting full operand; otherwise `Syntax` at token start. Unsupported token starts fail there; commas and glued operators receive no special grammar.

6. **R24–R27, R32:** For bare/caret/tilde/hyphen operands, any `-`/`+`, or at least three fields without an exact wildcard field, forces full-version parsing and wrapped `VersionError`. Otherwise partial validation errors are `Syntax` at operand start: at most three nonempty canonical numeric/wildcard fields, with no numeric field after a wildcard. Missing fields are wildcards. Bare one/two-numeric-field operands expand to padded inclusive lower and exclusive next-major/minor `-0` upper; zero numeric fields add no comparisons. Checked increments reject overflow without carrying.

7. **R28–R32:** Caret bumps major when major is positive or numeric-field count is one; otherwise minor when minor is positive or count is two; otherwise patch. Tilde bumps major only for count one, otherwise minor. Reset lesser fields and use exclusive `-0` uppers. All-wildcard caret/tilde is `Syntax` at token start; increment overflow is at operand start after the prefix. Any standalone `-` forces whole-arm three-token hyphen shape validation before operand parsing. Parse both endpoints lower-first before wildcard rejection or expansion; wildcard rejection points to its endpoint. Full hyphen upper is inclusive; partial upper uses next major/minor `-0`.

8. **R16–R18, R22, R26, R31, R33, R37:** Comparisons within an arm are conjunctive; contradictions are valid. Default prerelease admission additionally requires an explicit prerelease operand at the candidate’s exact core tuple in that same arm. Build and generated upper bounds grant no anchors; explicit prerelease lower bounds retain them. OR arms cannot share admission. `include_prerelease=true` bypasses only admission, preserving every comparison and generated `-0` bound; extrema always use default admission.

9. **R38–R40, R45:** Intersection means existence of any valid version, tested across arm pairs, rather than overlap among samples. Default-policy prerelease witnesses need admission from both arms; stable witnesses need none. Respect discrete adjacency: tuple minimum is `-0`; a prerelease’s immediate successor appends `.0`; a stable version’s successor is next core tuple’s `-0`, carrying patch/minor/major. No successor exists beyond the maximum core tuple. Arbitrary identifier lengths/counts forbid finite prerelease sampling.

10. **R41–R44:** Canonicalization uses default admission per original arm. Keep strongest lower/upper bounds, with equality contributing both and strictness winning equal-precedence ties; strip build. Discard arms lacking any discrete admissible witness. Preserve every explicit anchor of surviving arms, including out-of-bounds anchors, sorted numerically. Print exactly `[LOWER;UPPER;pre=ANCHORS]`, using `*` for missing bounds and `-` for no anchors. Deduplicate and ASCII-sort complete strings, join with ` || `, or print `EMPTY`; perform no merging or subsumption.

11. **R47–R53, R59:** Validate globally in this order: duplicate package names, duplicate labels, all candidates, all range leaves. Within phases follow package/input order and depth-first left-to-right child order; validate even irrelevant branches/candidates. Names/labels may be empty and are exact case-sensitive strings; labels are unique only within a package. Root-leaf paths are empty. Union/intersection evaluate the same candidate, with empty union false and empty intersection true. No constraints admits every valid candidate, including prereleases. Packages are independent; preserve order and inputs, and return the first unsolved package without partial selections.

12. **R54–R60:** Apply preference only after all constraints: Highest/Lowest use precedence; StableFirst chooses the greatest qualifying stable if one exists, otherwise greatest prerelease. All ties favor earliest candidate position. `NoSolution.labels` is a minimum-cardinality subset of whole constraints excluding every supplied candidate under the selected include policy—not an inclusion-minimal subset or an intersection over hypothetical versions. Sort each competing label subset by ASCII bytes and choose the lexicographically smallest vector. No candidates requires an empty diagnostic; nonempty candidates cannot have one.
