1. **R1–R2:** Deliver one Rust source file in `rust` fences, compilable with `rustc --edition 2024`, using only `std`, without inner attributes or inner documentation. Preserve the exact public API, public enum variants and `Match` fields, private `Router` fields, and required trait implementations; extra helpers must be private.

2. **R3, R18:** IDs count successful registrations only, starting at zero. Any failed addition must leave all state unchanged. Identical and structurally equivalent patterns remain separate registrations with distinct IDs and their own capture names; resolving never changes state.

3. **R4–R5:** For requests, truncate at the earliest raw `?` or `#` before any validation, even when the ignored suffix is malformed or non-ASCII. Then require a leading `/`: empty input, relative input, and an empty truncated head fail at byte 0. Patterns receive no truncation.

4. **R4, R6, R12–R13:** `/` alone has zero segments and is valid. Other empty segments are invalid at their start (`/a//b` → 3, `//` → 1). Validate preceding segments before rejecting a final slash at its own offset; consequently `/%GG/` fails at 1.

5. **R7, R12, R19:** Static and request segments permit raw ASCII unreserved bytes only, plus valid escapes. Report the first offending UTF-8 byte, not a character index. Matching is case-sensitive; `.`, `..`, and Unicode receive no normalization.

6. **R8:** An escape requires exactly two uppercase hexadecimal digits. Its decoded byte must be printable ASCII `0x20..0x7E`, excluding `/` and every unreserved byte. Every escape failure points to `%`, including lowercase hex, missing digits, encoded slash, controls, DEL, non-ASCII, and unnecessarily escaped unreserved bytes.

7. **R8, R19:** Decode exactly once and use decoded text for both comparison and captures. `%25` becomes literal `%`; `%253A` becomes literal `%3A`, without another decoding pass. Escaped `?`, `#`, `:`, and `*` are data; raw `?` and `#` invalidate patterns.

8. **R9–R11:** Recognize capture markers only when raw `:` or `*` begins a pattern segment. A `:` segment must have a complete name matching `[a-z][a-z0-9_]*`; any `*` segment is invalid regardless of its remainder. An escaped leading marker remains static text.

9. **R10, R12:** Validate segments left to right. Malformed or repeated capture names fail at the segment’s marker, even when a later character resembles a malformed escape. Duplicate names are checked within that pattern, case-sensitively; use `InvalidPattern` for additions and `InvalidPath` for requests.

10. **R9, R14–R15:** Parameters consume exactly one nonempty decoded segment, including decoded punctuation without interpreting it as syntax. Matching requires identical segment counts and complete segment matches. Return only captures, in pattern order, with an empty vector for routes without captures.

11. **R15–R16, R18:** Rank only fully matching routes, lexicographically by segment kind (`static=2`, `parameter=1`). The first differing position decides, regardless of later static segments; equal rank vectors choose the earliest successful registration, including equivalent patterns with different capture names.

12. **R12, R17, R19:** Validate the entire request head before returning a match or `NotFound`, including on an empty router or after an early route mismatch. Neither prefix nor substring matching is allowed; malformed later segments must still produce `InvalidPath`.
