1. **R1–R2, R29, R37, R39, R45:** Match every public type, field, variant, derive, and method signature exactly; keep heap internals private. Use one std-only Rust 2024 file, without inner attributes/docs. `iter` must return `std::vec::IntoIter<Item>`.

2. **R3–R5:** Trim only leading/trailing `0x20` bytes; all-space or empty input gives `EmptyKey`. Validate the entire trimmed key before lookup: first byte ASCII letter, subsequent bytes ASCII letter/digit/hyphen. Consecutive/trailing hyphens and unlimited length are valid. Report the first invalid byte’s offset in the **original input**, including leading spaces; non-ASCII fails at its first UTF-8 byte.

3. **R5, R10, R13, R24, R28, R42:** ASCII-lowercase valid keys everywhere, including returned items and key-bearing errors. Precedence is validation → lookup/duplicate → operation-specific checks → capacity. Valid absent `get` returns `Ok(None)`; other keyed mutations return canonical `Missing`. Duplicate push always errors, even for identical data or a full queue.

4. **R6, R15–R16:** Rank by signed priority ascending, then value **UTF-8 byte length** ascending, then oldest insertion first. Neither key nor value contents break ties. Preserve values exactly, including empty strings, Unicode, whitespace, and NUL. Compare all `i64` values directly without overflow-prone subtraction.

5. **R7, R17, R19, R27:** Retained new keys get the youngest age; reinsertion after removal gets a new age. Priority/value updates preserve age even across leaving and rejoining ties. Failures and discarded proposals cannot change existing ages or order. Age bookkeeping must not overflow into panics or incorrect ordering.

6. **R8, R11–R14, R17–R20, R26:** Length counts only retained keys; empty peek/pop return `None`. Peek/get return independent owned clones, and reads never affect ordering. Pop removes the full-order best; remove returns the named item at any rank. Every moved slot must remain correctly indexed. Queues remain independent.

7. **R19, R21–R28, R44:** Decrease/increase are strictly directional; equality errors for both, with exact current/requested priorities. Successful calls return the old priority. Replace returns the old value, permits identical/empty values, and recomputes rank. These updates preserve length and age; worsening an existing bounded item never triggers eviction. Every error is atomic.

8. **R37–R42:** `new` is unbounded; every `usize` capacity, including zero/MAX, is valid without proportional preallocation. Below capacity, push returns `Inserted`. At full nonzero capacity, only a proposal strictly better than the current worst is retained, returning `Evicted(old_worst)`; a priority/length tie loses because the proposal is youngest. Otherwise return `Discarded(proposal)`. Zero capacity discards every valid nonduplicate proposal.

9. **R38, R43:** `set_capacity` immediately retains at most the new limit and returns removals in full **worst-to-best** order, including youngest first on priority/length ties. Zero removes everything; increasing/removing the limit evicts nothing. Survivors retain their ages.

10. **R29–R33, R48:** Merge collisions use canonical keys. KeepSelf preserves the entire receiver item; TakeOther copies source priority/value while retaining receiver age. Reject chooses the first collision in the source’s **pre-merge rank order**, not lexical order, and leaves both queues and capacities unchanged. Detect rejection before any transfer or trimming, even at receiver capacity zero.

11. **R30, R34–R36, R47–R48:** Successful merge processes the entire source in pre-merge best-to-worst order as though the receiver were unbounded. New keys receive receiver ages younger than all original receiver items, ordered by source rank—even into an empty receiver. Then trim once to receiver capacity; never use repeated bounded pushes. Source becomes empty and reusable; both capacities remain unchanged.

12. **R35, R45–R47:** Merge counts classify every original source item before trimming: noncollisions moved, TakeOther collisions replaced, KeepSelf collisions discarded. Counts sum to original source length; successful Reject has no replacements/discards. Only final capacity removals enter `evicted`, worst-to-best. Iterators own a detached best-to-worst snapshot, support both ends and exact remaining length, and survive subsequent queue mutation.
