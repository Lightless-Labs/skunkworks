1. **R1, R16, R41:** Both endpoints ±10^18 are supported; larger magnitudes return `Range`. Check bounds without overflowing on `i128::MIN`. Exactly 10^18 is `one quintillion`.

2. **R2–R8:** Encoding uses exact lowercase spellings and spacing. Zero is only `zero`; negatives start `minus `. Hyphenate only nonmultiple-of-ten values 21–99; teens and exact tens have no hyphen.

3. **R9–R10:** Hundreds start with `one` through `nine` plus ` hundred`. Append ` and ` only for a nonzero remainder; exact hundreds have no `and`.

4. **R11–R15:** Emit nonzero three-digit groups in descending scale order, omitting zero groups. Use cross-group ` and ` only before a present units group of 1–99 with a higher group present—even across omitted groups. Internal and cross-group `and` can coexist.

5. **R18–R21, R39:** Empty input wins first. Otherwise scan the entire input for invalid bytes before checking structure; report the first invalid byte’s original UTF-8 offset. Never trim or lowercase; non-ASCII characters fail at their first byte.

6. **R22–R24, R39:** After lexical validation, check spaces and hyphens together from left to right. Each needs an immediately adjacent lowercase letter on both sides; adjacent delimiters fail at the first delimiter. Finish this phase before dictionary checks.

7. **R24–R27, R40:** Both delimiter types split tokens; token errors use the first letter’s byte offset. Scan the entire token stream for exact dictionary membership before arithmetic; the first unknown token wins, including over an earlier potential `Range`.

8. **R27–R28:** `minus` is allowed only as the first token; every later occurrence is `InvalidWord`. Initial `minus` sets the sign even with a following hyphen. A lone `minus` proceeds with magnitude zero to canonical comparison.

9. **R29–R32:** Relaxed arithmetic starts with both accumulators zero. Number words add to `group`; `zero` and `and` do nothing; `hundred` multiplies the entire current group by 100. No operation supplies an implicit one.

10. **R32–R34, R41:** Every scale adds `group × scale` to `total`, then clears `group`; repeated or ascending scales receive no structural rejection. After every arithmetic token, reject mathematical `total + group > 10^18`, allowing equality. Detect oversized additions and multiplications without overflow or panic.

11. **R34–R39:** The first arithmetic range violation wins even if later tokens would change the calculation. Otherwise apply the sign to the final magnitude, with zero remaining zero, then re-encode. Lone `minus`, standalone `and`, and bare scales therefore reach `NonCanonical`.

12. **R17, R36–R38, R42:** Acceptance requires byte-for-byte equality with the canonical encoding of the calculated value, compared against the original input including `minus`. Report the first differing byte, or the shorter length for a prefix; `one-hundred` fails at 3 and `twenty one` at 6.
