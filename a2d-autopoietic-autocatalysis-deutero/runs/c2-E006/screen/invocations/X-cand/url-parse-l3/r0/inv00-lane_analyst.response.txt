1. **R1, R18–R19, R30:** Implement the full supplied API, including IPv6, codecs, normalization and resolution; “level 1” does not limit this task. Match all public declarations and derives exactly. Use one Rust 2024, std-only source file inside Rust fences, without inner attributes/comments. Preserve value equality, deterministic results and unchanged arguments.

2. **R3–R6:** Error precedence is empty input → global byte scan → scheme → `//` marker → userinfo → host → port → components. Scan the entire original input first; the earliest byte outside `0x21..=0x7e` wins even over an earlier structural defect. Scheme uses the first colon anywhere; missing colon reports input length. Validate its first/subsequent bytes separately. Missing `//` reports `colon+1`; extra slashes are not consumed as authority.

3. **R7–R9, R15:** Authority stops at the first `/`, `?` or `#`; inspect `@` and host/port only inside it. A second `@` wins over empty userinfo or invalid host; report that second occurrence. A sole leading `@` reports its position. Otherwise preserve all userinfo, including colons. Component colons and `@` never affect authority parsing.

4. **R9, R19–R21, R27:** Ordinary hosts split at their first colon, must be nonempty, and permit only letters, digits, `.`, `-`, `_`; no DNS-label restrictions apply. Only a leading `[` selects IPv6. Find its first closing bracket, validate the interior before the suffix, and report invalid/missing IPv6 at `[`. Accept standard-library IPv4-embedded forms, reject zones, retain lowercase uncompressed interior without brackets. Invalid suffix reports immediately after `]`; brackets elsewhere are invalid ordinary-host bytes.

5. **R10–R11, R17:** Absent port colon means `None`; an empty port errors immediately after its colon. For nonempty ports, scan **all** bytes for the first nondigit before checking leading zeros or numeric range. Thus a late nondigit beats an earlier leading-zero/range defect. Reject multi-digit leading zero, zero, overflow and values above `65535` at port start; accept `1` and `65535`. Arbitrarily long digits must not panic; retain explicit default ports.

6. **R12–R18:** Split fragment at the first `#`, then query at the first `?` before that fragment. Further delimiters belong to their selected component. Present-empty query/fragment are `Some("")`, distinct from absence. Empty path becomes `/`; otherwise preserve it. Fold only scheme and host case; preserve raw component spellings, escapes and dot segments. Apply the later escape rules, not R16’s level-1 literal rule.

7. **R22–R24, R29:** Decoding is identical for all components: `+` stays `+`, literals include raw UTF-8, and either hex case is accepted. Validate escape syntax throughout the input before checking decoded UTF-8; a later malformed escape beats earlier invalid UTF-8. Report malformed escapes at `%`; map UTF-8 `valid_up_to()` back to the originating literal byte or `%`. Decoded NUL/control characters are valid; long valid inputs have no semantic size limit.

8. **R25, R29:** Encode UTF-8 bytes using uppercase, exactly two-digit escapes. Always preserve alphanumerics and `-._~`; additionally preserve only `:` for UserInfo, `/` for Path, `/?` for Query, and `/?#` for Fragment. Encode `%`, `+`, spaces, `@`, `&`, `=` and non-ASCII bytes. Empty input stays empty, and decoding an encoding must recover the original text for every component.

9. **R26–R28:** After successful port validation, validate userinfo → path → query → fragment, skipping absent components and the synthetic `/`. Each component completes escape and UTF-8 validation before proceeding: invalid UTF-8 in userinfo beats a bad path escape. Rebase codec errors to original URL byte offsets while retaining raw text. Host/port escapes remain invalid under their existing rules; escaped delimiters never change structure.

10. **R31–R34:** Normalization rejects missing raw leading `/` before escape validation, but otherwise accepts arbitrary literal UTF-8/characters. Validate the entire path before processing segments. Split only on raw `/`, retain empty segments, and decode solely to recognize exact `.`/`..`. Each `..` pops one entry, including an empty entry; excess parents are ignored. Final decoded navigation adds one empty segment. Preserve retained spelling and hex case; root, repeated/trailing slashes and idempotence matter.

11. **R35–R36, R40:** Resolution always parses the base, then normalizes its path, before scanning the reference—even for absolute references. Empty reference is allowed. A colon strictly before the first `/`, `?` or `#` selects absolute parsing; otherwise leading `//` selects network-relative parsing using the base scheme. Parse before normalizing either replacement path. Absolute errors use reference offsets; network errors use constructed `scheme:reference` offsets. Neither branch inherits base query or fragment.

12. **R37–R40:** Ordinary references use the same query/fragment split. Empty path inherits normalized base path and inherits base query only without an explicit `?`; nonempty path never inherits query. Fragment always comes solely from reference. Leading `/` replaces path; otherwise merge after the normalized base path’s last raw slash. Reconstruct and parse the absolute URL **before** normalizing the merged path, retaining userinfo, IPv6 brackets and explicit ports. Reference errors use constructed-string offsets; normalization errors are always `ResolveError::Path`.
