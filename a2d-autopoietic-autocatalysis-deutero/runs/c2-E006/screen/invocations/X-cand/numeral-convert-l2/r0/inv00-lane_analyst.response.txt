1. **R2–R4, R24:** Validate `from` before `to` (`which=0`, then `1`), or addition’s base (`which=0`), before anything else. Accept only 2..=36 and report the actual invalid radix.

2. **R3, R24:** Validate style next: `group` accepts 0..=8 and `min_width` accepts 0..=256, including both endpoints. Either violation returns `BadStyle` before inspecting operands.

3. **R4, R24:** Addition must fully validate left before inspecting right. A left separator or leading-zero error beats even an empty or invalid-tag right operand. Operand numbers are 0 and 1 respectively.

4. **R5–R8:** Never trim input. Check raw emptiness first; otherwise, if any `#` exists, its first occurrence defines a mandatory tag boundary. The prefix must exactly match the input radix’s decimal spelling; otherwise return `InvalidTag { index: 0 }`. Only a valid tag with an empty payload returns `Empty`.

5. **R7, R9–R12:** Error indices count UTF-8 bytes in the complete original operand, including its tag. Only ASCII digits and letters are digits; letters accept either case. A later `#`, whitespace, sign, non-ASCII byte, or digit outside the radix is invalid.

6. **R11–R12, R24:** Scan the entire payload for invalid digits, ignoring underscores, before checking separators or leading zeros. Return the earliest invalid byte even if a malformed underscore or leading zero occurs earlier.

7. **R13, R15:** Then return the earliest underscore without a digit immediately on both sides. Leading, trailing, consecutive, and underscore-only separators fail; arbitrary spacing between valid separators is allowed, regardless of output `group`.

8. **R14–R15:** Only after separators pass, reject a first digit of zero when there are at least two digits, excluding underscores from the count. Report the payload-start byte offset. Single `0` passes; `00` and `0_1` fail.

9. **R1, R16–R17, R25:** Parse positional values without tags or underscores, and perform conversion and addition exactly for arbitrarily long inputs supported by memory. Machine-sized accumulation, wrapping, saturation, and numeric overflow errors are incorrect.

10. **R17–R19:** Conversion renders in `to`; addition renders its exact sum in `base`. Start with the shortest representation, rendering zero as exactly `0`. `upper` controls output letters only.

11. **R20–R23:** Pad with zeros to at least `min_width` digits without truncating longer results, then group from the right, including padding. Group 0 disables underscores; otherwise the first group may be shorter. Never emit tags, signs, whitespace, or trailing underscores. Padded output may be invalid as subsequent input.

12. **R26; exact API/build contract:** Keep both operations stateless and pass `BaseStyle` by value. Preserve every specified public item, field, variant, signature, and required derive. Use one std-only Rust 2024 source file without inner attributes or inner documentation comments.
