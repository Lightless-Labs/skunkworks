1. **R1–R2:** Validate period even for zero capacity: `new(0, 0)` returns `ZeroPeriod`. Every nonzero `u32` period is valid; successful construction stores the supplied capacity and period, with no entries and pending zero.

2. **R3–R4:** Accept all `u64` keys and `i64` values, including their extrema and zero. Capacity counts distinct keys, regardless of values. Resident frequencies must always remain within `1..=7`; new keys start at 1.

3. **R9–R10, R27:** Count each get, remove, and enabled put exactly once, including misses and updates. Increment pending first; if it reaches period, age once and reset it immediately. Period 1 ages before every counted operation; `u32::MAX` must work without overflow.

4. **R12, R14, R18, R27:** Boundary aging precedes lookup, credit, replacement, eviction, and deletion—even on misses or an empty cache. A boundary insertion starts at frequency 1 without undergoing that boundary’s aging.

5. **R17, R23:** A zero-capacity put returns `Disabled` before counting or changing anything. Gets and removes still count while disabled. Resizing back above zero enables puts again.

6. **R11, R19–R20, R25:** Both aging mechanisms use ceiling division: 3 becomes 2 and 7 becomes 4. Explicit aging supports every round count through 255; zero is a complete no-op. It preserves pending, capacity, and global recency, including when frequency buckets merge.

7. **R5–R7, R25:** Maintain one global oldest-to-newest recency order. Eviction and snapshot order by frequency first, then that recency—not numeric key or former frequency bucket. Snapshot returns independent entry copies without changing state.

8. **R13–R15, R26:** Hits and resident-key puts both add one credit, capped at 7, and move the key to newest—even when already saturated. Gets return the stored value; updates replace it, return `[]`, and never evict, including when full.

9. **R16:** Only a missing-key put can evict: remove exactly one priority victim when full, then insert at frequency 1 and newest recency. Return exactly `[]` or `[victim]`; select the victim using frequencies after any boundary aging.

10. **R18, R28:** Remove returns the deleted value or `None`, without crediting or touching survivors. Delete all metadata for that key; later reinsertion receives frequency 1 and newest recency, with no retained history.

11. **R21–R24:** Resize installs the requested capacity and repeatedly selects the current priority victim until entries fit, returning victims in removal order. It never counts, ages, or resets pending—even when emptying the cache. Growing or same-size resize preserves all entry metadata and returns `[]`.

12. **R8, R29–R30:** Capacity/pending accessors and snapshots have no side effects. Clones independently own all state, including pending and recency. Preserve the exact public API and required derives; produce a complete std-only Rust 2024 file with deterministic, synchronous behavior and no panics for documented inputs.
