1. **R1–R2, R12, R21, R36:** Preserve every specified signature, field, derive, and visibility; `Range`’s chosen fields must also be public under R1. Deliver one std-only Rust 2024 source file, fenced as requested, without inner attributes/docs. Structural `Version` equality includes build; precedence ignores it.

2. **R3–R6:** Parse core fields sequentially using maximal ASCII digit runs. At an empty field, end/dot/minus/plus means `MissingCore`; anything else means `InvalidChar`. Validate leading zero before overflow, both before the separator. First/second separators must be dots; after patch only end/minus/plus is allowed. Accept zero and `u64::MAX`; reject whitespace, signs, prefixes, Unicode, and extra core fields at the specified byte.

3. **R7–R9, R19–R20:** Process identifiers sequentially, pre before build. Within each identifier, the first invalid byte wins over its leading-zero error; an earlier identifier’s error wins over later errors. Empty identifiers report their start, including a terminating plus. Only all-digit pre identifiers prohibit leading zeros; their length is unlimited. Build permits zeros; hyphens, including a lone hyphen, are content. Preserve case, spelling, and order.

4. **R10–R11:** Compare numeric core tuples first, then pre; a stable release exceeds every prerelease at that tuple. Numeric pre identifiers precede nonnumeric ones and compare by length then bytes, without integer conversion. Nonnumeric identifiers use case-sensitive ASCII order. After equal corresponding identifiers, the shorter list wins. Build never breaks a precedence tie.

5. **R12–R16, R22–R23, R33:** Tokenize only on ASCII space/tab/CR/LF; whitespace-only is `Empty { at: 0 }`. Only standalone `||` separates arms. Leading/consecutive separators report their own start; trailing separators report total input length, including whitespace. Earlier malformed arms win. Comparisons within an arm are conjunctive, including duplicates and contradictions. Unsupported token starters produce `Syntax` before operand parsing.

6. **R14–R15, R25, R27:** Explicit comparators choose the longest operator prefix and require a nonempty digit-starting operand; failure is `Syntax` at token start. Otherwise always parse a full version—even for partial-looking operands—and wrap its error at operand start, leaving nested offsets operand-relative. Bare/caret/tilde/hyphen operands instead use R25’s dispatch: any minus/plus, or at least three fields without an exact wildcard field, forces full-version parsing.

7. **R24–R27, R33:** Partial operands allow at most three nonempty fields: canonical, fitting decimal numbers followed only by exact `*`, `x`, or `X` fields; omitted fields are wildcards. Partial validation failures are `Syntax` at operand start. Zero numeric fields add no comparisons. One/two numeric fields expand to padded inclusive lower and exclusive next-major/minor `-0` upper. Full bare versions mean equality.

8. **R28–R29, R32:** Caret bumps major when major is positive or only one numeric field exists; otherwise minor when minor is positive or two numeric fields exist; otherwise patch. Tilde bumps major for one numeric field, otherwise minor. Reset lesser fields and give upper bounds pre `0`; retain full lower suffixes. All-wildcard operands fail at token start. Increment overflow never carries and reports `Syntax` after `^`/`~`, at operand start.

9. **R30–R32:** Any standalone minus triggers arm-shape validation first: exactly lower, minus, upper; otherwise error at the first minus before parsing operands. Parse lower then upper before checking all-wildcard endpoints or expanding bounds. All-wildcard endpoints fail at their own starts. Lower is inclusive; full upper is inclusive, partial upper uses exclusive next-major/minor `-0`. Expansion overflow reports the endpoint being expanded.

10. **R17–R18, R22, R26, R31, R33–R37:** Default prerelease admission requires an explicit prerelease operand with the candidate’s exact core tuple in that same arm, plus satisfaction of every comparison. Build and generated upper bounds grant nothing; explicit prerelease lower endpoints do grant admission. `include_prerelease` bypasses only admission. Extrema always use default admission, parse every candidate in order before selecting, report the first invalid candidate, return original strings, and resolve precedence ties by earliest index; empty/no-match inputs return `None`.

11. **R38–R40, R45:** Intersection asks for any valid witness across pairs of arms, not sampled candidates. Default-policy prerelease witnesses need their tuple anchored in both arms; stable witnesses need no anchors. Respect the discrete domain: least pre is `-0`, immediate prerelease successor appends `.0`, and stable successor advances the core with carry and pre `0`. Beyond the maximum stable tuple no witness exists; open overlapping bounds may still contain nothing.

12. **R41–R45:** Canonicalize each original arm under default admission: strongest lower/upper, equality supplying both, strict winning equal-bound ties, build stripped. Discard arms without an actual discrete admitted witness. Preserve every distinct explicit anchor tuple of surviving arms, even outside bounds, sorted numerically. Print exactly `[LOWER;UPPER;pre=ANCHORS]`, using `*` for absent bounds and `-` for no anchors. Deduplicate identical strings, ASCII-sort, join with ` || `, or emit `EMPTY`; perform no merging or subsumption.
