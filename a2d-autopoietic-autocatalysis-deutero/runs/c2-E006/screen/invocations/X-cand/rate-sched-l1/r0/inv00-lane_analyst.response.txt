1. **R1, R18:** Each scheduler starts at time 0. All three methods check time first; `now < last_successful_time` returns `TimeReversed`, overriding every other error. Equal timestamps are allowed; time never advances implicitly.
2. **R1–R2:** Every `Ok` records `now`, including `Ok(None)`. Every `Err` leaves all state unchanged, including the clock, job status, reservations, and insertion sequence.
3. **R3:** IDs must have 1–16 bytes inclusive, all ASCII `a`–`z`, `0`–`9`, or `-`. Empty, oversized, uppercase, whitespace, underscore, and non-ASCII IDs are invalid; hyphens alone are valid.
4. **R3–R5:** After the time check, insertion checks ID, then priority, then duplication. Priorities 0 and 9 are valid; 10–255 return `BadPriority`, even for an already reserved ID.
5. **R2, R5–R6:** Only successful insertion reserves an ID and assigns its FIFO position. Reservation survives cancellation and dispatch forever; failed insertions consume neither reservation nor sequence position. Sequence handling must not wrap and break FIFO ordering.
6. **R6, R11, R17:** Accept every `ready_at`, including 0, times before insertion, and `u64::MAX`. Readiness is inclusive (`ready_at <= now`); a past-ready job can already have substantial aging immediately upon insertion.
7. **R7:** After checking time, cancellation performs an exact ID lookup without syntax validation. An absent ID returns `Unknown`, including empty, malformed, uppercase, or oversized input.
8. **R8–R10, R2:** Cancelling any queued job succeeds, even before readiness. Repeated cancellation returns `Cancelled`; cancellation after dispatch returns `Completed`. These errors do not advance time.
9. **R11, R16–R17:** Only queued, ready jobs participate in selection. Future, cancelled, and dispatched jobs are excluded. An empty queue or a queue containing only future jobs returns `Ok(None)`.
10. **R12–R13, R17:** Zero aging disables aging without division. Otherwise use whole intervals since `ready_at`, including an increase exactly at each interval boundary, then cap at 9. Handle `u64::MAX` elapsed time mathematically without overflowing addition or narrowing before saturation.
11. **R14:** Highest effective priority wins. Every effective-priority tie, including ties caused by saturation at 9, uses earliest successful insertion—not readiness time, original priority, ID order, or container iteration order.
12. **R15–R16, R18:** Dispatch returns the selected ID and its effective priority at that call’s `now`, permanently marks it dispatched, and prevents further dispatch. All clocks, jobs, reservations, and FIFO ordering belong to their own scheduler instance.
