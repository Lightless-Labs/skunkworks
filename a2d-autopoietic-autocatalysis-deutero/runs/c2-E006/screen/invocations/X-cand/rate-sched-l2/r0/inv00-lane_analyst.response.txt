1. **R1, R11:** Calendar times and `Occurrence.at` are milliseconds; only `Cron::matches` takes absolute minutes. Match using `m % 60` and `(m / 60) % 24`, including `u64::MAX`, without overflowing intermediate arithmetic.

2. **R2, R4:** Validate the entire layout before parsing either field. The first ASCII whitespace byte other than space wins over all space-layout errors; otherwise report no space at `text.len()`, multiple spaces at the second space, or a sole leading/trailing space at that space. Every offset is an absolute UTF-8 byte offset.

3. **R3, R4, R9:** After layout, parse minute items left-to-right, then hour items left-to-right; an earlier item’s error wins. Empty items are errors at their starts, including a trailing comma pointing to field end. Repeated, overlapping, and numerically unordered valid items are allowed.

4. **R3, R7:** Within an item, a second slash produces `Syntax` there before base validation. With one slash, a base that is neither `*` nor a range produces `Syntax` at that slash before numeric validation—even for an otherwise valid number.

5. **R5, R9:** Validate each numeric fragment’s entire ASCII-digit syntax before checking leading zeros or value. Report the first non-digit byte, or fragment start when empty; only then report `Number` for multi-digit leading zeros. Only an exact `*` is a wildcard; other nonnumeric text follows these syntax rules.

6. **R6–R8:** Validate range left endpoint, right endpoint, then ordering; only the first dash separates endpoints, so another dash is invalid right-fragment text. Bounds errors point to endpoint starts; descending errors point to the dash. Base errors precede every step error.

7. **R5, R6, R8, R10:** Base limits are inclusive `0..=59` and `0..=23`; step limits are inclusive `1..=60` and `1..=24`. Step syntax and leading-zero errors precede `Step`. Huge digit strings must never panic. Ranges include endpoints; stepping starts at the range’s left endpoint, or zero for `*`, and may select only the start.

8. **R12–R14:** IDs require 1–16 bytes, each an ASCII lowercase letter, digit, or hyphen; priorities allow 0–9. `add` checks `BadId`, `BadPriority`, `Duplicate`, then cron parsing, in that order. Failure reserves nothing and changes nothing; successful IDs remain reserved permanently and establish insertion order.

9. **R15, R16, R26:** The first successful poll includes boundary zero through `now`; later intervals exclude the previous successful poll time and include `now`. Newly added jobs use only subsequent intervals, including when earlier polls had no jobs. Empty calendars still advance the watermark.

10. **R17, R18, R22:** Accept `now == 604800000`; reject larger values. Check reversal against the last successful poll before checking range, with no reversal check initially. Failed polls preserve all state. Successful polls consume the entire interval even without emissions; identical-time repeats return empty.

11. **R19–R21, R24:** `All` emits every matching boundary; `Once` emits the latest matching boundary **within this interval**; `Skip` emits only when `now` itself is an eligible matching minute boundary. Preserve scheduled timestamps rather than substituting poll time, and emit each boundary only once per job despite overlapping cron items.

12. **R23, R25:** Globally merge by ascending timestamp, then descending priority, then successful insertion order. Priority never overrides timestamp, and ID spelling never breaks ties. Keep calendars and crons independent and use no wall clock.
