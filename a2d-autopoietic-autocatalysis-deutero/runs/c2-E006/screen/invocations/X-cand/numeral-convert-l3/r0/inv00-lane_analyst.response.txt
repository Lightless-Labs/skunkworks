1. **R1, R23:** Encoding accepts both endpoints ±(2^120−1), but rejects every value beyond them with `OutOfRange`, including `i128::MIN`; avoid overflowing when checking its magnitude. Decode uses `Range`, never `OutOfRange`.

2. **R2–R8, R30:** Both systems directly represent signed values without sign characters. Balanced ternary uses uppercase `T` = −1 and base +3; negabinary uses base −2. Encode zero as exactly `0`, and every nonzero value with the shortest sequence without a leading `0`.

3. **R7–R8:** Negative inputs require the specified remainder choices: balanced ternary selects the congruent digit in {−1,0,1}; negabinary selects the Euclidean remainder in {0,1}. Rust’s negative `%` results cannot be used unadjusted. Reverse the emitted digits.

4. **R9–R12, R11:** Checksummed output is exactly `payload:digit`, with one ASCII digit from `0` through `6`; otherwise output only the payload. Compute the weighted sum from the left starting at position 1, using character codes `T=2`, `0=0`, `1=1`, excluding the suffix.

5. **R13–R14, R32:** Do not trim input. Split at the first colon only. An empty input or empty payload returns `Empty` immediately, even if its suffix is malformed.

6. **R15–R16, R24:** Scan the entire payload before checking suffix syntax or evaluating numbers. Return `InvalidByte` for its first disallowed byte, including whitespace, signs, lowercase `t`, non-ASCII bytes, and `T` in negabinary. A later invalid byte defeats an earlier potential range violation.

7. **R13, R18, R22:** Error indices are zero-based UTF-8 byte offsets in the original input, not character counts. A non-ASCII payload character is rejected at its first byte; range errors identify the offending digit; every malformed suffix identifies the first colon.

8. **R17–R19:** A supplied suffix must consist of exactly one ASCII byte `0`–`6`. Empty suffixes, `7`–`9`, extra characters or colons, whitespace, and non-ASCII text all produce `InvalidChecksum`, before leading-zero or range checks.

9. **R5–R6, R20, R27:** After lexical and suffix validation, reject every multi-byte payload beginning with `0`, including all-zero strings. Single `0` is valid. No further canonical comparison is required.

10. **R21–R23, R32:** Evaluate left to right and check ±L after every digit; the first violating prefix returns `Range` immediately. All finite inputs must avoid arithmetic panics, including very long payloads and checksum sums; keep checksum arithmetic reduced modulo 7.

11. **R25–R26, R32:** Check a syntactically valid checksum only after leading-zero and prefix-range validation succeed. On mismatch, `expected` is the computed digit and `found` is the supplied digit. Overall precedence is `Empty` → `InvalidByte` → `InvalidChecksum` → `LeadingZero` → `Range` → `ChecksumMismatch`.

12. **R28–R29, R31:** Recode must fully decode with `from`, propagate the exact error unchanged, then encode with `to` and the requested checksum flag—even when both systems match. Recompute output checksums. Preserve the exact public API, required derives, determinism, and absence of retained state.
