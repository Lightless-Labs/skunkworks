1. **R1–R4:** Only an empty capacity vector is invalid; individual zero capacities are valid. Route using the full `u64` key before converting the remainder to `usize`; capacity and usage vectors follow shard-index order.

2. **R3, R5, R15, R35:** Support maximum keys, both `i64` value extremes, and full-range positive `u64` weights and capacities. Aggregate usage and global pinned weight require `u128`; avoid overflowing intermediate additions even when the final resident usage fits.

3. **R6–R9, R33:** Maintain one global oldest-to-newest order, including pins. Every successful `get`, including a pinned hit, moves its key newest; misses change nothing. R7’s side-effect prohibition applies to observational accessors, subject to the explicit `get` touch requirement.

4. **R10, R33:** `set_pin` changes only the pin bit, even for redundant calls; it never touches recency. Unpinning restores eviction eligibility at the entry’s existing position; an absent key returns `Missing`.

5. **R11–R12, R20, R31:** `remove` returns `Missing` for absence, then `Pinned` for a resident pinned key; otherwise it returns the deleted value without touching survivors. Every error from every operation preserves all state, including a failed replacement’s original value, weight, pin and recency.

6. **R13–R16:** Insert validation is strictly `ZeroWeight`, then destination-local `TooHeavy`, then `Blocked`. Exclude the old same-key entry from pinned feasibility regardless of its pin bit; accept equality in `other pinned weight <= capacity − proposed weight`. Finish validation before deleting anything.

7. **R14, R16, R19–R20:** A pinned same-key entry is replaceable, including weight changes and unpinning. After validation, subtract its entire stored weight before considering evictions; never report that replacement deletion as a victim. Store the supplied metadata and move the replacement newest, even if unchanged.

8. **R17–R19, R30:** Insert evicts the **oldest**, not newest, eligible entry in the destination shard, repeatedly if necessary. Skip pins and every other shard; capacity cannot be borrowed. Return actual victims in removal order and stop immediately when the new entry fits, including equality.

9. **R21–R25, R30:** Resize checks the shard ID first. For a valid shard, reject only when local pinned weight exceeds capacity, reporting that weight and capacity as `u128`; otherwise install capacity and evict local oldest unpinned entries until usage fits. Equality succeeds; zero succeeds only without local pins and removes all local entries. Other shards and survivor order remain unchanged.

10. **R26–R30:** Trim first compares **global** pinned weight with the `u128` target. If feasible, evict globally oldest unpinned entries only while total usage is **greater than** target; equality must neither evict nor attempt victim selection. Zero and `u128::MAX` targets are valid, overshooting is allowed, and capacities never change.

11. **R6–R7, R32, R34:** Snapshots contain each resident key exactly once, with its correct shard and metadata, in global recency order. Deletions free exactly stored weight; usage must match snapshot sums. Returned vectors, entries and cloned caches own independent state.

12. **R8, R17, R23, R27, R35:** Recency follows operation order, with no key-sorted or shard-sorted tie-breaking. The visible tests do not distinguish oldest from newest local eviction, verify pin-related recency, replace pinned entries, exercise trim equality, or cover maximum arithmetic; all remain required, deterministically and without panics on documented inputs.
