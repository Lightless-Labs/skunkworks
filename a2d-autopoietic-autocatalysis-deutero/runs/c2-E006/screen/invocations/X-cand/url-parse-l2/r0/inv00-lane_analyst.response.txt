1. **R1, R18–R19:** Implement the complete displayed API, including IPv6 and codecs; “level 1” does not authorize omitting later requirements. Match every public field, variant, signature, and derive. Submit one std-only Rust 2024 source file inside Rust fences, with no inner attributes or inner doc comments.

2. **R2–R5, R28:** Precedence is empty input → global byte scan → scheme → marker → userinfo structure → host → port → components. Scan the entire original input first: the earliest byte outside `0x21..=0x7e` wins over structural errors, including the first byte of raw non-ASCII. All offsets count bytes.

3. **R5–R6:** The scheme ends at the first colon anywhere, even after apparent component delimiters. No colon means `InvalidScheme` at input length; empty/nonletter-first scheme means offset 0; otherwise report the first forbidden scheme byte. Lowercase the scheme. Require two immediate slashes, reporting `MissingAuthority` at colon+1; additional slashes belong to the path and can expose an empty host.

4. **R7–R8, R15:** End authority at its first `/`, `?`, or `#`; inspect only that substring for userinfo and host/port. A second `@` wins over empty-userinfo or host errors. Exactly one leading `@` is invalid at that byte; otherwise preserve everything before it, including colons. Later component `@` and `:` bytes have no authority meaning.

5. **R9, R17, R21, R27:** Ordinary hosts split at the first colon after userinfo, including unbracketed IPv6-looking text. Reject an empty host at its start, even at EOF; otherwise reject the first byte outside letters/digits/`.`/`-`/`_`. Empty labels and leading dots/hyphens are valid. Lowercase only; escapes and misplaced brackets remain invalid host bytes.

6. **R19–R21:** Only a host starting `[` takes the IPv6 branch. Find its first closing bracket within authority; missing closure or an interior rejected by `Ipv6Addr::from_str` gives `InvalidIpv6` at `[`. Accept supported embedded IPv4, reject zones, and preserve lowercased interior spelling without brackets or compression. Validate interior before suffix: only end or `:` plus port is allowed; another suffix gives `InvalidHost` immediately after `]`. Ordinary hosts have `ipv6=false`.

7. **R10–R11, R21:** No port colon means `None`; an empty port errors immediately after its colon. For nonempty ports, scan every byte for nondigits before checking leading zero or range, so a later nondigit wins over earlier numeric overflow. Reject multi-digit leading zero, zero, values above 65535, and arbitrarily long overflow at port start; accept 1 and 65535 without panicking.

8. **R12–R18:** Split fragment at the first `#`, then query at the first `?` before that fragment. Further delimiters remain component content. Present empty query/fragment are `Some("")`, distinct from absence. An empty path becomes `/`; otherwise preserve it verbatim. Preserve userinfo/component spelling and explicit ports; perform no dot normalization or default-port removal.

9. **R16, R22–R24, R29:** Standalone decoding accepts literal UTF-8, copies `+` unchanged for every component, and decodes either hex case. Validate all escape syntax before decoded UTF-8: any later malformed escape beats earlier invalid decoded bytes. Report malformed/truncated escapes at `%`; accept decoded NUL and controls. No arbitrary length cap is permitted.

URL validation rebases these offsets and processes userinfo → path → query → fragment only after port validation. Precedence is per component: invalid userinfo UTF-8 beats a malformed path escape. 11. **R25, R29:** Encoding operates on UTF-8 bytes using uppercase, two-digit escapes. Common safe bytes are ASCII alphanumerics and `-._~`; extras are userinfo `:`, path `/`, query `/?`, fragment `/?#`. Encode everything else, including `%`, `+`, space, `@`, `&`, and `=`. Empty input stays empty; decoding an encoding must recover every original UTF-8 string.
