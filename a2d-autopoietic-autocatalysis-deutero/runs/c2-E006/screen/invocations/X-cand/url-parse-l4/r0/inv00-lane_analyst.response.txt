1. **R1, R18–R19:** Implement the entire supplied API, including IPv6, codecs, resolution, queries, and canonicalization; “levels” do not make later features optional. Match public visibility, field types, and derives exactly. Deliver one std-only Rust 2024 source file in Rust fences, without inner attributes/comments. Preserve `None` versus `Some("")` and value equality.

2. **R2–R8, R15:** Parsing precedence is empty → first globally forbidden byte → scheme → `//` → userinfo structure → host → port → components. The ASCII scan covers the entire URL, including components. Scheme ends at the first colon anywhere; missing colon reports `input.len()`. Require the next two bytes to be `//`; extra slashes end authority. Count `@` only inside authority; the second `@` wins over host errors, and empty userinfo errors at its `@`.

3. **R9–R11, R17, R27:** Ordinary hosts split at their first colon, must be nonempty, and allow only letters/digits/`.`/`-`/`_`, without DNS rules. Validate host before port. For ports: empty errors immediately after `:`; otherwise first scan **all** bytes for nondigits, then reject leading zero on multi-digit strings, then enforce `1..=65535`. Numeric failures report port start; arbitrarily long numbers must not overflow or panic.

4. **R19–R21:** Only a host starting `[` enters IPv6 parsing. Find its first closing `]` within authority; missing closure or an invalid interior reports the opening bracket. Validate the interior before checking suffix; suffix must be empty or `:` plus a valid port, otherwise report `InvalidHost` immediately after `]`. Preserve lowercase interior spelling without brackets or compression; ordinary hosts have `ipv6=false`. Unbracketed IPv6-like text still uses ordinary first-colon splitting.

5. **R12–R17, R26–R28:** Split fragment at the first `#`, then query at the first `?` before that fragment; later delimiters remain content. Empty explicit query/fragment are `Some("")`; empty path becomes `/`. After port validation, validate userinfo → path → query → fragment, retaining raw spellings and rebasing errors to URL byte offsets. Escape precedence is local to each component; host/port escapes receive ordinary host/port errors. Only scheme and host are case-folded.

6. **R22–R24, R29–R30:** Standalone decoding accepts literal UTF-8, treats `+` literally for every component, and accepts decoded controls/NUL. Validate escape syntax across the whole component before checking decoded UTF-8; a later bad escape beats earlier invalid UTF-8. UTF-8 errors map `valid_up_to()` back to the original literal byte or escaped byte’s `%`. Both hex cases work; long valid strings have no artificial limit, and operations remain pure and deterministic.

7. **R25, R46:** Component encoding uses uppercase bytewise `%HH` and always preserves only unreserved bytes, plus `:` for UserInfo, `/` for Path, `/?` for Query, and `/?#` for Fragment. Everything else—including `%`, `+`, `@`, `&`, `=`, spaces, and UTF-8 bytes—is escaped. Query serialization uses a separate safe set: only unreserved bytes stay raw, and spaces become `+`.

8. **R31–R34:** Path normalization rejects missing leading raw `/` before escape validation, then validates the **entire** path before processing segments. Split only on raw `/`; decode segments solely to recognize exact `.`/`..`. Retain other segments verbatim, including empty ones; `..` pops one entry even when empty. Terminal decoded navigation adds an empty segment. Preserve repeated/trailing slashes unless popped, hex spelling, root behavior, and idempotence; standalone literal UTF-8 is legal.

9. **R35–R36, R40:** Resolution always parses base, then normalizes its path, then globally scans reference—even for absolute references; empty reference is allowed. A colon strictly before the first `/`, `?`, or `#` selects absolute parsing, including malformed schemes. Otherwise initial `//` selects network-relative parsing using the normalized base scheme plus `:`. Absolute/network branches inherit no query or fragment, normalize their paths, and network parse offsets refer to the constructed absolute string.

10. **R37–R40:** Ordinary relatives with empty path inherit normalized base path and inherit base query only without an explicit `?`; nonempty paths use only reference query. Fragment always comes solely from reference. Absolute paths replace; other paths merge after base’s last raw slash. Reconstruct and parse the complete absolute URL **before** normalizing its path; Reference offsets belong to that constructed string. Preserve explicit ports and raw retained components; all normalization failures are `ResolveError::Path`.

11. **R41–R46:** Query parsing does not strip `?` or apply the URL ASCII scan. Discard empty `&` fields; split each remaining field at its first `=`; absent values are empty. Replace raw `+` before decoding. Process key decoding → empty-key rejection at field start → value decoding → next field, rebasing byte offsets. Merge decoded keys case-sensitively in first-appearance order. Serialization skips empty keys/zero-value entries, merges duplicates at their first **contributing** occurrence, preserves value order, and always emits `=`.

12. **R47–R52:** Canonicalization precedence is full URL parsing → path normalization → query parsing. Canonicalize userinfo/fragment by decoding then component encoding; render IPv6 through `Ipv6Addr::to_string()` in brackets. Remove only HTTP port 80 and HTTPS port 443. Encode normalized path **segment by segment** with unreserved bytes only, preserving encoded slashes and empty segments; perform no subsequent dot pass. Preserve explicit empty `?`/`#`, regroup query values by first key, and ensure idempotence without changing other APIs’ behavior.
