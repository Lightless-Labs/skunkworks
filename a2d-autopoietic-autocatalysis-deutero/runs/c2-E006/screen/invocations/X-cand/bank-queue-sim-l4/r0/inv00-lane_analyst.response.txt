1. **R1–R5, R39:** Preserve the exact public API and derives in one Rust 2024, std-only file. Validate capacity first, customer count second (4096 is legal), then original rows ascending: zero ID → duplicate earlier ID → bad priority → initial deadline overflow. Complete validation before simulation, including customers destined to balk.

2. **R7–R10, R41:** Sort arrivals by `(arrival ascending, priority ascending, ID descending)`. At every tick execute A–F exactly: Finish → existing-waiter expirations → entire arrival cohort → preemption → dispatch/inline finishes → remaining expirations. Coincident finishes beat deadlines; deadlines beat arrivals and dispatch.

3. **R11–R14, R42:** Admission uses the current waiting count and the unchanged server state throughout the cohort: capacity plus one if idle. Emit each Arrive immediately followed by Balk if refused. Priority, zero patience, and zero service never bypass capacity; accepted zero-patience arrivals retain their slots until later phases. Capacity zero still permits one arrival when idle.

4. **R15–R16:** Select by priority first, then paused before fresh within that priority. Paused ties use latest preemption timestamp ascending, then ID ascending; fresh ties use arrival ascending, then ID descending. Update the timestamp after every preemption. Preemption requires strictly better priority and compares against the queue before inserting the running customer.

5. **R8, R16–R19:** Perform at most one preemption in Phase D. Protection lasts only while `now < work_at`; at equality it ends, unless Phase A already finished the customer. Remaining service is `scheduled_finish - now`. Emit Preempt with the selected waiter’s ID; checked paused-deadline creation precedes subsequent dispatch arithmetic.

6. **R6, R14, R17–R18, R23, R26:** Patience is cumulative waiting only. Consume each queue segment on dispatch or expiration, preserve the unspent budget across active intervals, and schedule each paused deadline as `preemption_time + unspent_budget`. Renege reports all accumulated waiting, including earlier segments; `None` remains unlimited.

7. **R20–R22:** The simulation’s first dispatch has no switching cost. Every later dispatch pays it only when the ID differs from the most recently dispatched ID, remembered across idle gaps and zero-duration completions. Start occurs only once per customer; subsequent dispatches emit Resume, both reporting service remaining before dispatch.

8. **R12, R18, R22, R38–R39:** Check dispatch additions in order: `time + switch_cost` → WorkAt, then `work_at + remaining` → Finish; report the selected ID and dispatch time. Never try another waiter or prevalidate service arithmetic. Initial patience overflow applies even to eventual balkers; undispatched service overflow is irrelevant. Return only the first specified error, without a partial report.

9. **R9, R24–R26:** Existing waiters whose deadline equals now expire before dispatch. Fresh or newly paused zero-budget customers can nevertheless dispatch in Phase E before Phase F. Inline completion immediately follows Start/Resume and repeats selection without revisiting earlier phases. Zero service with positive switching cost remains active until its scheduled finish; active customers never expire.

10. **R19, R27–R28, R38, R40, R43:** Jump to the least pending arrival, finish, future work boundary, or waiting deadline; work boundaries run every phase without emitting a boundary event. Treat `u64::MAX` as a valid time, including successful zero additions. Preserve IDs/priorities and exact emission order; never use input or hash iteration order as an unstated tie-break.

11. **R29–R34:** Count accepted at admission, started only on first Start, and completions in Finish emission order. Busy time includes actual switching and active intervals of eventual renegers; waiting includes every accepted customer’s consumed segments; turnaround includes completed customers only. Elapsed is the last event’s absolute timestamp, including initial idle time. Empty valid input yields entirely zero statistics.

12. **R35–R37, R39:** Means use accepted and completed denominators respectively; utilization uses absolute elapsed. Scale before rounding, with zero-denominator statistics defined as zero. `rounded_ratio` itself returns None exactly for denominator zero and supports all u128 inputs with nearest, ties-to-even rounding without overflowing intermediates. Calls must be independent and leave inputs unchanged.
