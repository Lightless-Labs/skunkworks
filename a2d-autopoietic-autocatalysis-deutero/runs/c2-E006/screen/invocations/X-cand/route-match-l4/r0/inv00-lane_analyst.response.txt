1. **R1–R3:** Deliver one std-only Rust source file in `rust` fences, compiling with edition 2024; no inner attributes/docs. Match the public API and derives exactly, with private Router fields/helpers. Successful adds get contiguous IDs from 0; failures consume none and mutate nothing. Resolve/build are read-only.

2. **R4–R6, R12–R13, R19:** Resolve strips the first raw `?` or `#` and everything after it before path validation; even malformed/non-ASCII suffixes are ignored. Patterns have no such stripping. Empty/relative heads fail at 0. `/` has zero segments and no trailing flag; permit one final slash, reject interior empties (`/a//b` at 3, `//` at 1). Offsets are original UTF-8 byte offsets.

3. **R7–R8, R12, R19:** Raw segment data permits only ASCII unreserved bytes. Escapes require uppercase `%HH`, decoding once to printable ASCII excluding `/` and unreserved bytes; every malformed/noncanonical escape fails at `%`. Thus `%25` is valid, `%41` and `%2F` are invalid, and `%253F` decodes to literal `%3F`. Compare/capture decoded text case-sensitively; perform no further normalization.

4. **R9–R12:** Only raw leading `:`/`*` marks a capture; its entire remainder must match `[a-z][a-z0-9_]*`. Malformed or repeated names fail at the marker, regardless of later bad escapes. Parameters and wildcards share a case-sensitive name namespace. Validate left to right; a non-final wildcard fails at its own start before inspecting later segments. Use `InvalidPattern` versus `InvalidPath` appropriately.

5. **R9, R14–R15, R18–R19:** Parameters consume exactly one nonempty decoded segment. A final wildcard consumes zero or more remaining segments, joined with `/`; always include its capture, even when empty. Its prefix must match fully, and zero consumption introduces no separator. Return captures in pattern order. Validate the entire request before returning `NotFound`, including on an empty router; ordinary routes require complete matches.

6. **R16–R17, R26:** Rank eligible routes lexicographically using static `2`, parameter `1`, wildcard `0`; append terminal `3` only without a wildcard. First differing position wins, rather than total static count; exact termination beats an empty wildcard. Equal vectors choose the earliest successful registration among method-eligible routes.

7. **R13, R21–R23:** Strict requires matching trailing flags for candidacy, including for 405 calculations. Ignore/Redirect disregard flags for candidacy and rank. Ignore never redirects; Redirect compares only the selected winner’s flag and adds/removes the original encoded head’s final slash, preserving spelling and dropping suffixes. Root never redirects; errors never redirect.

8. **R20, R24–R26:** Methods must be nonempty ASCII `[A-Z]+`; validate them before every other argument. Filter path candidates by method before ranking. HEAD uses explicit HEAD candidates if any exist anywhere among path candidates, otherwise GET candidates; fallback retains GET’s ID/captures. No reverse fallback or implicit OPTIONS. A 405 lists all candidate methods, sorted/deduplicated, adding HEAD for GET, including lower-ranked candidates.

9. **R27–R30:** Add’s mandatory order is method → name syntax (`[a-z][a-z0-9_-]*`) → complete pattern → global name uniqueness → conflict. Conflicts require the same method, segment count, decoded statics, and corresponding segment kinds; capture names do not matter. Mere overlap is insufficient. Strict additionally requires equal trailing flags; other policies ignore them. Report the smallest conflicting ID.

10. **R31–R34:** Build’s mandatory order is exact name lookup → first duplicate supplied key in input order → first missing capture in pattern order → lexicographically smallest extra key → value validation. Unknown names win even when syntactically invalid. Duplicate detection includes unknown keys; keys undergo no validation/normalization. Wildcard keys are mandatory even for empty values; extra-key ordering is bytewise.

11. **R35:** Validate values in pattern order, independent of supplied order. Every byte must be printable ASCII `0x20..0x7E`. Parameters must be nonempty and slash-free; wildcards may be empty, otherwise require nonempty slash-separated components without leading/trailing/doubled slashes. Dot segments are valid. Never percent-decode supplied values: `%20` is literal text.

12. **R22, R36–R37:** Build from decoded statics and supplied values, leaving only unreserved bytes raw and encoding everything else as uppercase `%HH`; preserve wildcard separators. An empty wildcard contributes no segment or preceding separator. Emit `/` for root; otherwise preserve the registered trailing slash under every policy. Never emit query/fragment syntax. Build uses the named route regardless of method/rank, and resolving its output may select another route.
