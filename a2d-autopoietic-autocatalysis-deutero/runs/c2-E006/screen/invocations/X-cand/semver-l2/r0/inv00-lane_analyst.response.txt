1. **R1–R2, R12, R21:** Deliver one std-only Rust source file in `rust` fences, compatible with edition 2024, without inner attributes/docs. Match every specified public signature, field, variant, and derive; keep `Range`’s representation opaque while making its chosen fields public. `Version` equality includes build metadata; precedence does not.

2. **R3–R6:** Version parsing uses byte offsets, accepts no trimming/prefix/sign/Unicode, and requires exactly three core numbers. At each field, consume maximal ASCII digits; absent digits mean `MissingCore` only at EOF, `.`, `-`, or `+`, otherwise `InvalidChar`. Check leading zero, then overflow, then separator. Before patch, EOF/`-`/`+` means `MissingCore`; other nondots mean `InvalidChar`. After patch, only EOF/`-`/`+` is legal.

3. **R7–R9, R19–R20:** Process identifiers sequentially, pre before build. Validate each whole identifier’s characters before checking its numeric leading zero; an earlier identifier’s error beats any later error. Empty identifiers report their start, including `+` terminating empty pre. Pre numeric identifiers never overflow; build permits leading zeros. Hyphens—including a lone hyphen—are content. Preserve case, spelling, order, and absent suffixes as empty vectors.

4. **R2, R9–R11:** Accept core `u64::MAX`. Compare core numerically, then put releases above prereleases. Numeric pre identifiers precede nonnumeric ones and compare by length then bytes, without integer conversion; nonnumeric identifiers compare case-sensitive ASCII bytes. Equal common identifier prefixes favor the shorter list. Build never breaks precedence ties.

5. **R12–R15, R27, R33:** Only ASCII space/tab/CR/LF separate range tokens; surrounding such whitespace is allowed, and whitespace-only input gives `Empty { at: 0 }`. Operators must touch operands. Explicit comparators choose the longest operator, then require a nonempty digit-starting full-version operand: failure is `Syntax` at token start; version failures wrap at operand start with unchanged operand-relative nested offsets. Thus `==`, `!=`, commas, parentheses, and standalone `&` are unsupported.

6. **R16–R18, R22–R23, R33:** Tokens within an arm are conjunctive; arms are disjunctive. Contradictions remain valid. Only standalone `||` separates arms; glued pipes remain operand content and fail parsing. Leading/consecutive separators give `Empty` at that separator; trailing separators give `Empty` at the entire input length, including whitespace. Process arms left to right, so earlier malformed content beats a later empty arm.

7. **R17–R18, R22, R26, R31, R33:** Every prerelease candidate additionally needs an explicit prerelease operand in the same arm with its exact core tuple, and must still satisfy every bound. Stable candidates need no admission. Build metadata and generated bounds never grant admission; anchors never cross tuples or arms. Explicit prerelease endpoints retain admission when expanded into lower bounds.

8. **R24–R25, R27:** For bare/caret/tilde/hyphen operands, any `-` or `+`, or at least three dot fields with no exact wildcard field, forces full-version parsing and wrapped `VersionError`. Otherwise partial parsing allows at most three nonempty fields, canonical `u64` decimals followed only by exact `*`, `x`, or `X`; failures give `Syntax` at operand start. Missing fields are wildcards; numeric fields cannot follow wildcards. Explicit comparators never use this partial grammar.

9. **R24, R26, R32:** Count numeric fields, not written fields: bare `1`, `1.*`, and `1.x.X` share bounds. Zero numeric fields add no comparisons but still exclude prereleases by default. One numeric field expands to inclusive padded lower and exclusive next-major upper; two use next-minor upper. Every generated upper has pre `["0"]`. A full bare version is equality, ignoring build precedence.

10. **R28–R29, R32:** Caret/tilde require a numeric field; all-wildcard operands give `Syntax` at token start. Lower bounds retain full operands’ pre/build. Caret bumps major if major is positive or `k=1`, otherwise minor if minor is positive or `k=2`, otherwise patch; tilde bumps major only for `k=1`, otherwise minor. Reset lower fields and use upper pre `["0"]`; consequently `^0`, `^0.0`, and `^0.0.0` differ.

11. **R30–R32:** Any standalone `-` triggers an arm-shape check before operand parsing: require exactly `lower - upper`, otherwise `Syntax` at the first standalone minus. Parse lower then upper before rejecting all-wildcard endpoints or expanding bounds. Lower is inclusive; full upper is inclusive, partial upper exclusive at next major/minor with pre `["0"]`. Every increment overflow is `Syntax` at the responsible operand start—after `^`/`~` where applicable—with no carry.

12. **R21, R34–R35:** Parse every candidate in input order, including nonmatches, before returning an extremum; the first invalid candidate wins with its original index and unchanged error. Empty/no-match lists return `Ok(None)`. Apply ordinary arm admission and precedence, return the original input string, and retain the earliest input index on ties, including differing builds; do not sort or deduplicate.
