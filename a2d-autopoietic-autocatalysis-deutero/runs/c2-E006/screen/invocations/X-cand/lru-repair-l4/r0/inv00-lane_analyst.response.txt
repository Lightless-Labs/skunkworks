1. **R1–R3, R9:** Zero capacity is valid; zero weight is never valid. Validate `ZeroWeight` before `TooHeavy`, using the stored capacity, before any flush, eviction or mutation—even for dirty replacements. Support full integer ranges without computing an overflowing `used + weight`.

2. **R4–R7, R40, R43:** Maintain independent, duplicate-free LRU and dirty-write orders. Snapshot is oldest LRU first, not numeric key order. Successful gets and puts move keys to newest LRU; misses change neither order. Reading dirty data never changes dirty-write order.

3. **R10–R13, R43:** Every successful dirty put and every successful `mark_dirty` moves the key to newest dirty-write order, including already-dirty keys. `mark_dirty` preserves LRU and emits exactly `Dirty`. Missing keys return `Missing` without effects. Successful clean puts remove dirty-order membership.

4. **R14–R15, R39, R42:** `remove` checks existence before cleanliness: return `Missing` for absent keys and `Dirty` for dirty residents, atomically and without events. Clean removal returns the stored value, subtracts its full weight exactly once, removes both order memberships, preserves survivor order and emits only `Remove`.

5. **R16–R20, R40:** Each dirty flush emits `FlushStart` with the current resident value before exactly one synchronous callback. Success cleans the entry, removes dirty-order membership and emits `FlushOk`; failure emits `FlushErr` and preserves value, weight, dirtiness and both positions. Neither outcome touches LRU; clean entries produce no callback or flush events.

6. **R21–R23:** Explicit `flush` selects oldest dirty-write keys, independently of LRU, and leaves entries resident. Zero is a complete no-op; `usize::MAX` is valid. Stop immediately on failure, returning `Err`, while retaining earlier successful cleanings and events; the failed key remains the next dirty candidate.

7. **R24–R27, R39:** Capacity eviction always selects oldest eligible LRU, regardless of cleanliness. Flush dirty victims before deletion; append `Evict` only after successful deletion and after their flush events. Failure preserves the victim, emits no `Evict`, stops further attempts and retains completed evictions. Successful victim lists follow removal order.

8. **R28–R29:** After validation and before selecting capacity victims, a clean replacement must flush a dirty old same-key entry using its **old** value. A dirty replacement coalesces old data and must not flush the same-key entry, even when it was already dirty.

9. **R30–R32, R39:** Keep the old same-key entry resident and exclude it from victim selection throughout room-making. Credit its weight: continue while `used - old_weight > capacity - new_weight`; missing keys have old weight zero. Equality fits. Install and touch the replacement only after all required work succeeds; never report or log its overwrite as an eviction.

10. **R19, R27, R33, R42:** Failed puts install nothing and emit no `Store`; preserve the old value, weight and LRU position among survivors. A successful preliminary old-entry flush remains committed, leaving it clean even if a later victim fails. Otherwise preserve its original dirty state/order. Completed victim work and events also remain committed; return `FlushFailed`, not a partial success list.

11. **R34–R38:** `evict_to` stops at `used <= target` and never changes capacity; targets at least `used` are complete no-ops, and zero removes everything unless flushing fails. Resize installs capacity and emits `Resize` only after eviction succeeds. Failure retains old capacity and completed progress. Equal-capacity and growing resizes still emit `Resize`, without callbacks or evictions.

12. **R8, R32, R41, R44–R45:** Logs contain exactly the specified events and payloads, with no implicit boundary events; successful puts emit `Store` last. `events`, snapshots and clones are independently owned. Draining clears only the log. Preserve deterministic, synchronous, std-only behavior without panics on documented inputs; callback panics are excluded.
