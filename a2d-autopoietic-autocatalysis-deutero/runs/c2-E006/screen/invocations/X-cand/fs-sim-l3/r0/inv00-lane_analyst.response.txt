1. **R1–R2:** Match every public type, derive, variant and signature exactly; keep storage private. Deliver one std-only Rust 2024 source file in Rust fences, without inner attributes/comments. Each instance starts independently with only `/`.

2. **R3, R16, R23:** Scan the entire original path for NUL before other validation; report its first UTF-8 **byte** offset. Only the empty string is otherwise invalid. Preserve spaces, Unicode, backslashes, case and non-special dot-containing names verbatim.

3. **R4, R19, R21–R22:** Normalize completely before lookup, starting relative paths at the entry-time cwd. Eliminate empty components, exact `.` and exact `..`; clamp traversal above root. Thus `/missing/../file` addresses `/file`, and trailing `/` never requires a directory.

4. **R5–R6, R18, R23:** Traverse canonical prefixes in order: report the first absent prefix as `Missing`, or the first file that must be traversed as `NotDir`. These beat final-entry errors. Creation requires an existing directory parent; report a file immediate parent as `NotDir(parent)`. Error paths are canonical absolute paths.

5. **R7–R9, R14, R17, R22:** After parent checks, mkdir returns `Exists` for either existing kind; write replaces files but returns `IsDir` for directories; read also returns `IsDir` for directories. Every spelling normalizing to root follows the explicit root rules, including mkdir’s `Exists("/")`.

6. **R9–R13, R17:** Preserve arbitrary bytes, including NUL and invalid UTF-8; empty data creates a file, and replacement truncates completely. Copy input data and return owned results. Every failed mutation must preserve all state; valid inputs must not panic.

7. **R10–R11, R15:** ls requires a final directory, otherwise `NotDir`; list only immediate child basenames with stored kinds. Sort by Rust String ordering, case sensitively and independently of insertion order; empty directories return an empty vector.

8. **R19–R20, R24, R36:** cwd starts at `/` and is returned as an owned canonical string. Only successful chdir changes it, after lookup and a final directory check. Every other operation, including successful rename/remove, leaves cwd unchanged.

9. **R25:** Rename validates/normalizes `from` first, then `to`, before any lookup. A source validation error wins; otherwise destination validation beats source lookup and root checks. After both validate, either normalized endpoint being `/` yields `Root`.

10. **R26–R28:** Rename then checks, strictly: source parent, source existence, source-directory `Busy`, destination parent, existing destination-directory `Busy`, same-path success, then directory `Cycle(destination)`. Busy includes cwd equality; missing source still fails on self-rename. Destination-parent errors beat Cycle.

11. **R29–R32:** Only afterward apply overwrite rules: existing destination plus false gives `Exists` regardless of kinds/nonemptiness; true gives `NotDir` for directory→file, `IsDir` for file→directory, and `NotEmpty` for directory→nonempty directory. Successful moves preserve the whole source tree and bytes, replacing only an allowed destination.

12. **R28, R32–R36:** Remove checks validation, normalized-root `Root`, parent traversal, entry existence, directory `Busy`, then nonempty status, in that order. Busy beats recursive deletion; otherwise recursive removes whole trees, while files/empty directories accept either flag. All containment/subtree checks use whole components, preserving prefix-sharing siblings such as `/ab` when operating on `/a`.
