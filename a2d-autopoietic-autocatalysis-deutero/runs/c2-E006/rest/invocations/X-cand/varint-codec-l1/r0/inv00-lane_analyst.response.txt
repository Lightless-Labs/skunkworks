1. **R1:** Submit one Rust source file inside a single `rust` fence, with no prose; it must compile under edition 2024 using only `std`, without inner attributes or inner documentation comments.

2. **R2–R3:** Preserve the three public function signatures exactly; additional helpers must be private. Define the public `Error` enum with exactly the specified variants, field names, `usize` types, and four derives. Returned cursors are absolute indices, not byte counts.

3. **R4–R6:** Encode least-significant seven-bit groups first, setting continuation only when another group follows. Encoding must be minimal: zero is `[0]`, and `u64::MAX` is nine `0xff` bytes followed by `0x01`.

4. **R7–R8:** Validate `start > input.len()` before indexing or arithmetic involving the cursor. That returns `StartOutOfBounds { offset: start }`; equality is valid but decoding there returns `Truncated`.

5. **R9, R11–R12:** Stop immediately at the first clear continuation bit. Ten-byte restrictions apply only if decoding actually reaches byte ten; trailing malformed bytes cannot invalidate an already terminated integer.

6. **R8, R10:** Missing any required byte, including the first, means `Truncated { offset: input.len(), start }`. The offset is the absolute end of input, and `start` remains this integer’s original cursor.

7. **R6, R11–R12:** On the tenth byte, only `0x00` and `0x01` are valid. Any larger payload or set continuation bit returns `Overflow` at that byte, even at end of input; never inspect byte eleven or shift beyond the `u64` width.

8. **R13:** Decoding need not be canonical: accept redundant zero groups, including nine `0x80` bytes followed by `0x00`. Do not reject an encoding merely because re-encoding its value would be shorter.

9. **R14, R18:** Decode exactly `count` consecutive integers in encounter order, advancing each time from the previous returned cursor. After the requested count, ignore all remaining bytes, including malformed ones.

10. **R15–R16:** Batch start validation precedes the zero-count shortcut. Invalid start plus zero count still errors; valid start plus zero count returns `(vec![], start)` without reading, including at end of input or on an empty slice.

11. **R17:** Return the first failed integer’s error unchanged, with that integer’s starting cursor rather than the batch start. Discard previously decoded values; do not return a partial vector or continue decoding.

12. **R18:** Handle arbitrary `usize` starts and counts without arithmetic or capacity panics. In particular, avoid unchecked `start + 9` and count-based allocation that can overflow before an inevitable decoding error; only allocation exhaustion is exempted.
