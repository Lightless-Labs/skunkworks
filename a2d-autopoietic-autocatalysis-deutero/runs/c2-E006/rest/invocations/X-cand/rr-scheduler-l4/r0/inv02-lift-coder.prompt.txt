R2. Validate all input before simulation, returning only the first error in the order described by the following validation clauses. Even empty jobs do not bypass parameter validation.

R3. First quanta.len() must be 1..=8, otherwise Error::LevelCount.

R4. Next inspect quanta in ascending index order. Each must be 1..=1000; return Error::Quantum { level } for the first invalid element.

R5. Next switch_cost must be 0..=1000, otherwise Error::SwitchCost.

R6. Next jobs.len() must be at most 64, otherwise Error::TooManyJobs.

R7. Next inspect job rows in input order. At each row the first check is whether id equals any earlier row id; if so return Error::DuplicateId { index }.

R8. At that row next require arrival in 0..=1000; otherwise Error::Arrival { index }.

R9. At that row next require level < quanta.len(); otherwise Error::InitialLevel { index }. Level 0 is the highest priority.

R10. At that row next require bursts.len() odd and in 1..=31; otherwise Error::BurstCount { index }.

R11. At that row then inspect burst positions from 0 upward: even positions are CPU lengths in 1..=1000, odd positions are I/O delays in 0..=1000. Return Error::Burst { index, position } at the first invalid position. Earlier row errors win over any later row errors.

R12. The alternating vector starts and ends with CPU. I/O may have zero duration; CPU may not. The arrival describes when the first CPU burst becomes ready.

R13. Start at time 0. External arrivals are admitted by increasing (arrival, input index), regardless of input sorting or id values.

R14. There is one FIFO ready queue for each level. An external arrival joins the tail of its initial level queue.

R15. Choose the head of the lowest numbered nonempty queue whenever a dispatch is needed. Neither a higher-priority arrival nor a wake interrupts a selected dispatch.

R16. At the start of each scheduling iteration, admit every pending event whose timestamp is at most the current time before selecting a job. Events retain their own timestamp even when processed later.

R17. Remove the selected head before charging any cost. This choice is locked: events during a dispatch cost may join queues but cannot replace the selected job.

R18. Before executing the selected job, add switch_cost to time exactly when a last positive-work dispatch id exists and differs from the selected id. The first dispatch is free.

R19. Admit events through the time after that cost. Then execute uninterrupted for min(remaining CPU work, selected quantum). Cost does not consume quantum.

R20. The selected quantum is quanta at the job's level when selected. Run.level is that level, before any demotion or promotion.

R21. Advance time by consumed CPU ticks. Emit exactly one Run, with start after cost, end after execution, and finished true exactly when the entire job completes. Never merge Runs, including adjacent Runs of the same id.

R22. After execution, admit all pending events through the Run.end, including events exactly at Run.end, before requeuing the running job. Arrivals during execution are never delayed until its next dispatch.

R23. If CPU work remains in the current burst, demote one level capped at the last level and requeue at that level's tail after events at Run.end. Each dispatch starts with a fresh quantum; no quantum balance carries across bursts or dispatches.

R24. If a CPU burst ends, burst completion takes precedence over quantum exhaustion, including equality. Do not demote. If it is the final CPU burst, record completion at Run.end.

R25. If that burst has a following I/O delay, block immediately at Run.end until Run.end + that delay, and advance to the next CPU burst. Blocked jobs are not in any ready queue.

R26. On waking, set the job's level to max(0, level of the dispatch that started that I/O minus 1), then append to that level's tail. Promotion occurs even for a zero-delay I/O.

R27. The wake generated by the just-finished burst is included when admitting events through Run.end. A zero-delay wake therefore competes immediately at that endpoint.

R28. Order pending events by (timestamp, kind, input index), with external arrivals kind 0 and I/O wakes kind 1. At a tie all external arrivals precede all wakes, and each kind follows input index, not id or blocking order.

R29. External arrivals and wakes never incur CPU time themselves. Once all events at a timestamp are admitted, FIFO order within each queue persists until selection or later tail insertions.

R30. After execution, remember its id as the last dispatched id. Same-id consecutive dispatches have no cost even across zero-duration I/O; different levels do not affect this comparison.

R31. If no ready job exists but an event remains, advance to the next event timestamp. Any positive time skipped is idle: append that half-open interval and clear the last dispatched id. The next dispatch after positive idle is free.

R32. Merge adjacent idle intervals into one pair when the old end equals the new start. Never include dispatch costs in idle, never emit zero-length idle, and emit no trailing idle after the last completion.

R33. Schedule.end is the time all jobs have completed. Initial idle begins at 0 when needed. For no jobs, end is 0 and all vectors are empty.

R34. Schedule.stats contains one Stat per input job in input order, regardless of completion order.

R35. Stat.completion is the end of the final CPU Run. Stat.turnaround = completion - arrival.

R36. Stat.waiting = turnaround minus the sum of that job's CPU lengths minus the sum of its I/O delays. Thus waiting includes time in ready queues and its own dispatch costs, excludes blocked time, and never counts time before arrival.

R37. mean_waiting_x100 and mean_turnaround_x100 are the arithmetic means of the corresponding Stat fields multiplied by 100 and rounded to nearest integer, with exact halves rounded upward. Use exact integer arithmetic, not per-job rounding. For example total 1 over 8 jobs yields 13; total 1 over 3 yields 33.

R38. Both mean fields are 0 for no jobs; otherwise every input job contributes once, including jobs initially at lower levels.

R39. All time and statistics calculations are exact u64. The stated bounds guarantee no overflow; no wall-clock, randomness, threads, global state, or external services affect the result.

6. **R15, R19–R21, R23:** Execution is uninterrupted despite arrivals or wakes. Use the level and quantum at selection, consume `min(remaining CPU, quantum)`, and emit one unmerged Run starting after cost. Each dispatch gets a fresh quantum; `finished` means the entire job has completed.

8. **R24–R28:** A nonfinal CPU completion blocks until `Run.end + I/O delay`; its next CPU uses a fresh quantum. At wake, promote from the level of the dispatch that started I/O, saturating at 0. Include the newly generated zero-delay wake in endpoint admission, ordered with all other endpoint events by R28.

9. **R18, R30–R32:** Remember the executed id after every Run, including one that blocks or finishes. Clear it only when positively advancing time while idle; another job already ready after a completion can therefore incur a switch cost. Event admission alone never clears it.

Waiting includes the job’s own switch costs and ready-queue delays, including after wakes, but excludes blocked time and time before arrival.

12. **R37–R39:** Compute each mean from the total across all jobs, multiply by 100, then divide with nearest rounding and exact halves upward; never round individual contributions or use floating point.
