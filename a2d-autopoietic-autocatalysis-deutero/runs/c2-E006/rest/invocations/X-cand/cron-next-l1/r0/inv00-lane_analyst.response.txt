1. **R1–R2:** Match the exact public API and derives, including variant names and payload types. Deliver one std-only source file, compiling with `rustc --edition 2024`, inside Rust fences; no inner attributes.

2. **R3–R4:** Split only on literal ASCII spaces, preserving every empty piece. Check the count before any validation: empty input counts as one; repeated, leading, and trailing spaces affect the count. Tabs/newlines remain inside fields. Domains are inclusive; weekday 7 is invalid.

3. **R5–R6:** Validate fields minute through weekday, stopping at the first failing field. Within each field, scan all bytes for illegal characters before parsing any items; the first illegal byte overrides earlier item errors in that field. Offsets are field-relative UTF-8 byte positions, including for non-ASCII characters.

4. **R7:** Preserve empty comma-separated items and process items left to right. An empty whole field fails at offset 0; consecutive commas produce an empty item after the preceding comma; a trailing empty item starts at the field’s byte length.

5. **R8:** Validate the complete item structure before interpreting any numbers. Only `*`, digits, or `digits-digits`, optionally followed by `/digits`, are valid. Empty operands, extra slashes/hyphens, starred endpoints, and other malformed structures yield `InvalidSyntax` at the item start—even if a numeric substring would otherwise fail.

6. **R9–R10:** For each number, leading-zero detection precedes checked `u32` accumulation, which precedes bounds checking. Thus a long zero-prefixed number yields `LeadingZero`; a value exceeding `u32::MAX` yields `NumberOverflow`; a fitting numeric base outside its domain yields `OutOfRange`. All point to that number’s start.

7. **R11:** After structure validation, fully validate the start number, then the end number, then check reversal. An invalid end overrides reversal; reversal reports the end number’s start. All base/endpoint and reversal errors precede every step-number error.

8. **R12:** Steps use leading-zero and overflow checks, then `BadStep` unless within the inclusive full-domain width: 60, 24, 31, 12, or 7. Zero is always invalid; the maximum width is valid. A step exceeding the selected range’s length remains valid.

9. **R13–R14:** Unstepped numbers select only themselves; stepped numbers extend through the domain maximum. Stars span the whole domain, starting at its minimum—including 1 for month/day-of-month. Ranges include both endpoints; equal endpoints are valid.

10. **R15–R16:** Always include the selection start, then repeatedly add the step while within the end; the end appears only if reached. Union all items without duplicates, and return ascending values regardless of item order or overlap.

11. **R17:** Do not perform calendar realizability checks or cross-field validation. Individually valid fields such as February and day 30 must parse successfully.

12. **R18:** Equality compares selected sets plus two independent flags recording whether day-of-month and day-of-week were each exactly the one-byte field `*`. Consequently `*` differs from `*/1`, `*,*`, or an equivalent full range in either day field; other syntax differences with identical sets and flags compare equal.
