1. **R1–R2:** Deliver one std-only Rust source file in `rust` fences, compiling under edition 2024, without inner attributes or inner doc comments. Match every public type, field, variant, function signature, and required trait; helpers may be private.

2. **R3:** Validate byte length, not character count: 1–24 ASCII bytes inclusive. The first byte must be `a`–`z`; subsequent bytes may also be digits or hyphens; the final byte cannot be a hyphen. Internal consecutive hyphens are allowed. Preserve invalid names verbatim in errors.

3. **R7, R10:** Validate all names even with empty roots or unreachable catalog entries. Visit roots first, then each catalog package followed by its release dependencies, using input order throughout. Return the first invalid name with the exact zero-based site syntax; finish name validation before any duplicate check.

4. **R8–R9:** Complete the duplicate-package pass before examining duplicate versions anywhere. Report the first repeated package occurrence; otherwise report the first repeated version encountered within a package, traversing packages and releases in input order. Unreachable duplicates and releases with differing dependencies still fail.

5. **R4:** Compare all three `u32` components lexicographically; `Before` is strictly exclusive. Caret fixes the major when positive, otherwise fixes major zero and the positive minor, otherwise requires the exact version—including `^0.0.patch`. Handle zero and `u32::MAX` directly without incrementing bounds.

6. **R5–R6, R17:** Constraints are conjunctive, including repeated roots and dependencies from different selected releases. Error lists contain every active constraint, deduplicated and ordered by variant `Exact`, `AtLeast`, `Before`, `Caret`, then lexicographic version. An empty constraint list matches every version.

7. **R11:** At every node, active constraints come from roots and dependencies of all currently selected releases only. Activate every dependency of a newly selected release before checking errors, even if that release becomes contradicted. Cycles and self dependencies are legal; never assign a package twice.

8. **R12:** Check all active missing packages before any conflict or candidate failure. Report the lexicographically smallest missing name, regardless of discovery order or whether an incompatible selection activated it.

9. **R13–R14, R17:** After missing checks, report the lexicographically first incompatible selected package as `Conflict`; only then check all unselected active packages for `NoMatch`. Report the first zero-candidate name before making another assignment. Both errors carry complete canonical active constraints.

10. **R6, R15:** Choose the lexicographically smallest unselected active package and its highest matching version, regardless of root or release order. Never backtrack or downgrade: a later contradiction returns `Conflict` even when another version would solve the graph.

11. **R10, R16, R20:** Empty roots return an empty selection only after full validation. Empty catalogs are valid; an active absent package yields `Missing`, while an active present package with no releases yields `NoMatch`. Success contains exactly activated packages, sorted by name; preserve inputs and deterministic choices.

12. **R18–R20:** Match every error prefix, field order, separator, and spelling exactly, with no spaces or trailing newline. Encode free-text UTF-8 bytes using uppercase `%HH`, preserving only ASCII letters, digits, `.`, `_`, `-`; empty text stays empty. Versions use unpadded decimal components; constraints use literal operators and commas. Canonicalize caller-constructed error lists too, without catalog access.
