1. **R1–R2, R17, R25, R34:** Preserve every declared public type, variant, field, signature and derive; expose no extra public helpers. Retain earlier APIs when adding later ones. Deliver one std-only Rust 2024 source file inside Rust fences, without inner attributes or inner documentation comments.

2. **R5–R9:** Validate tier count first: zero → `Empty`, above 64 → `TooMany`. Then scan input order: `Some` must strictly exceed the previous finite bound, initially zero; nonfinal `None` immediately yields `Unbounded`. Only after scanning check `MissingFinal`. Complete validation precedes arithmetic, including zero quantity and unused tiers.

3. **R3–R4, R10–R14, R16:** Bounds are cumulative and inclusive. Graduated allocation follows input order; hitting a bound exactly leaves the next tier unused. Add each used tier’s start once and retain zero-priced positive-unit bands. Unused tiers charge nothing. Flat positive usage produces band 0; zero usage produces no bands. Never sort by price or merge bands.

4. **R15–R16, R24:** Check each used band’s product plus start, then its addition to the running total. The first overflowing used band supplies its original index; return no partial charge. Exact `u64::MAX` succeeds, including maximum quantities. Neither minimums nor later discounts can rescue overflow.

5. **R17–R24:** `quote` always remains graduated; graduated `bill` uses the same charge. Volume validates everything, then selects the first inclusive bound covering positive quantity, otherwise final `None`, charging all units and one start in one original-index band. Flat charges ignore mode. Minimum adjustment is positive-usage-only, leaves charge/bands unchanged, and makes total `max(charge.amount, minimum)`.

6. **R26–R27, R30:** Proration checks month length first—only 28–31—then `start <= end <= days`, then credits. Validate even with zero fee. Empty service intervals, including `[days,days)`, succeed only with no credits; they yield zero active days and amount.

7. **R28–R31:** Scan credits in input order. At each index, first require `start <= credit.start < credit.end <= end`; only then check against the previous credit’s end. Thus same-index `Credit` beats `CreditOrder`, but an earlier order failure beats later invalidity. Adjacency is legal; overlaps and unsorted ranges are rejected, never merged.

8. **R31–R33:** Subtract all credit lengths before computing `fee * active_days / days`; the denominator is the whole month. Round once: floor, ceiling without increment on exact division, or nearest with exact halves choosing the even integer. Use sufficiently wide exact arithmetic for maximum fees; never round daily charges.

9. **R35–R37:** Global invoice discount validation precedes everything. Complete the entire name pass before any meter discount or calculation. At each input index, validity precedes duplication. Names require 1–32 UTF-8 **bytes**, exclude ASCII controls, DEL, `|` and `:`, and otherwise preserve whitespace/non-ASCII literally. Uniqueness is exact and case-sensitive, without normalization.

10. **R38–R41, R47:** After names, process meters in input order: validate meter discount, run `bill`, run `prorate`, check their combined base, compute discount/line, then immediately add line total to subtotal. Component errors are wrapped in `Meter` with the input index; subtotal overflow is unwrapped `InvoiceOverflow`. Later failures never outrank an earlier failure; full discounts skip nothing.

11. **R39–R44, R47:** Check base overflow before discounting. Meter discount is floor of `base * bps / 10000`; subtotal sums discounted line totals. Invoice discount then uses that subtotal; credit is capped at the remaining amount. Products must be exact at maximum values; rates 0 and 10000 are valid. Retain zero-total lines; empty invoices succeed after global validation.

12. **R40, R42, R45–R46:** Sort successful lines lexicographically by UTF-8 bytes, preserving original error indices. Render usage before minimum, then minimum adjustment, monthly, meter discount and line total. Prefix each literal name with its byte length and colon; use unpadded decimal integers and pipes. Every line ends with one LF; append exactly the specified `TOTAL` line even when empty, with no extra whitespace.
