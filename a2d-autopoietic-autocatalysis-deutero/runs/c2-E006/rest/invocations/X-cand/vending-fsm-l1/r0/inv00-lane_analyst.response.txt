1. **R1–R2:** Deliver one std-only file compiling under Rust edition 2024, inside only `rust` fences; no inner attributes/docs. Match every public signature, field and variant; keep Machine fields private. Every other listed type needs Clone, Debug, PartialEq and Eq.

2. **R5–R8:** Constructor precedence is EmptyCatalog first, then supplied product order, checking each product’s ID syntax → duplicate → price before advancing. A duplicate beats its own invalid price; an earlier bad price beats any later invalid ID.

3. **R6, R8:** IDs must contain exactly 1–8 lowercase ASCII letters; empty, uppercase, Unicode, whitespace and punctuation fail with the entire original ID. Prices 1 and 100 are valid; 0 and 101–65535 fail.

4. **R4, R9, R20–R21:** Start with zero credit, no selection and empty escrow. Machines, snapshots and receipts own independent values; modifying a snapshot or making subsequent calls cannot alter earlier outputs. Preserve ID bytes without normalization.

5. **R3, R10–R11:** Accept only coins 1, 3, 4 and 10. Check denomination before the inclusive 100-credit limit: even at full credit, an invalid coin yields BadCoin. Handle every u16 input without overflow; rejected insertion changes nothing.

6. **R9–R10, R12–R13:** Successful insertion appends in insertion order regardless of selection. Selection checks exact, case-sensitive catalog membership before SameSelection, without syntax validation; selecting the same ID fails even at zero credit. Replacement preserves money; failure preserves the previous selection.

7. **R14–R17, R25:** Vend precedence is strictly NoSelection → Underpaid when credit < price → ExactPayment when credit > price → canonical-tender validation. Selected with zero credit means Underpaid; no selection wins regardless of credit or tender.

8. **R3, R22, R24:** Canonical tender uses unlimited coins, greedily taking 10, then 4, then 3, then 1 while possible. This is not minimum-coin optimization: price 6 requires `[4,1,1]`, rejecting `[3,3]`. Any count arrays use the separate ascending order `[1,3,4,10]`.

9. **R22–R24:** Compare the canonical vector with a descending-sorted copy of escrow. Insertion order cannot affect acceptance, and stored escrow must retain its original order even when comparison fails.

10. **R23, R25:** TenderMismatch reports the first differing zero-based index, with expected from canonical tender and found from sorted escrow. Exact equal totals ensure a differing pair exists before either vector ends; never invent a missing-coin sentinel.

11. **R16–R18, R20–R21:** Successful vend returns the selected ID, its price and empty change, then clears all transaction state. Refund always succeeds, including at zero credit, returns every coin in reverse insertion order and clears selection too. Products remain available indefinitely.

12. **R14, R19–R21, R24:** Every Err preserves all pre-call state and reports pre-call values, including after TenderMismatch. Complete validation before mutation; result-returning methods must not panic for any arguments. Reads never mutate, and no automatic selection, refund or vend occurs.
