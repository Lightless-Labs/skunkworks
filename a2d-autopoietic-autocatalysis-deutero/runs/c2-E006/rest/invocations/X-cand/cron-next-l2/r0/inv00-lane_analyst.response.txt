1. **R1–R2, R19:** Deliver one std-only Rust source file for edition 2024, inside a single `rust` fence, with no inner attributes. Preserve every specified public name, signature, field, variant, and derive; `Cron` may have private internals.

2. **R3–R5:** Split only on literal ASCII spaces, preserving empties; check the piece count before any field validation. Empty input counts as one piece. Validate fields in their stated order; offsets are UTF-8 byte positions within the failing field. Day-of-week 7 is invalid.

3. **R5–R7:** For each field, scan its entire byte sequence for illegal characters before processing any items. Its first illegal byte beats earlier syntax, numeric, or empty-item errors in that field, but cannot beat an error in an earlier field. Tabs, newlines, and non-ASCII characters are illegal.

4. **R7–R8:** Preserve empty comma items and process items left to right; report an empty item's starting offset, including field length for a trailing empty item. For each nonempty item, validate its complete structure before reading numbers; malformed structure yields `InvalidSyntax` at the item start.

5. **R9–R11:** Validate the start number completely, then the end completely: leading zero, checked-u32 overflow, then domain bounds for each. Only afterward check reversal, reporting the end's start offset. Thus an invalid start beats an invalid end, and all base errors beat step-number errors.

6. **R9–R12:** A step gets leading-zero and u32-overflow checks before its bounds check. Zero or a value above the full domain width yields `BadStep`, not `OutOfRange`; widths are 60, 24, 31, 12, and 7. A step exceeding the selected interval's length remains valid.

7. **R13–R16:** Unstepped numbers select singletons; stepped numbers extend to the domain maximum. Stepped stars begin at the domain minimum, including 1 for month/day-of-month. Always include the start, include the end only if reached, union overlaps, and return unique ascending values regardless of item order.

8. **R17–R18:** Accept impossible date combinations during parsing. Equality compares selected sets plus a separate “exactly `*`” flag for each day field: `*` differs from `*/1`, `*,*`, or an equivalent range there. Other equivalent syntax compares equal.

9. **R19–R22:** Both datetime methods must validate Year → Month → Day → Hour → Minute before checking membership or returning `None`. Years are inclusive 2000–2399; day validity depends on the actual month and Gregorian leap rules. In this interval, 2000 is leap; 2100, 2200, and 2300 are not.

10. **R23–R24:** Compute actual Gregorian weekdays with Sunday=0 and 2000-01-01=Saturday=6, counting leap days. `matches` requires all five memberships simultaneously; day-of-month and day-of-week use AND, regardless of their exact-star flags.

11. **R25–R26:** `next_fire` finds the earliest match strictly after the argument, including later minutes on the same date. Cross actual calendar boundaries, skip nonexistent dates without clamping, include the final supported minute as a possible result, and return `None` after exhaustion or at that maximum.

12. **R10, R15, R25–R27:** Prevent arithmetic overflow during decimal accumulation, step advancement, and calendar rollover. Impossible schedules must terminate with `None`. Queries must be repeatable and read-only, with no shared mutable state allowing another parse or query to alter an existing `Cron`.
