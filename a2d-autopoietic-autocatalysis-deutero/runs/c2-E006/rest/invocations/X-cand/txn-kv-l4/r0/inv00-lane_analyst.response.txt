1. **R1–R2, R38:** Preserve every exact signature, public field/variant, and required derive, including `Error`. Submit one std-only Rust 2024 source file in Rust fences, without inner attributes/docs. Use no I/O, wall clock, threads, or global state; stores are independent. Strings use Rust ordering without normalization; values may be empty.

2. **R3–R5, R10–R12, R22, R35:** Validate time first everywhere except `new`; backwards time changes nothing, while admitted time persists through later errors. Equal times are valid. Then validate transaction existence before key/range checks; key before read-only, read-only before TTL arithmetic, range before cursor/parsing. All later errors preserve everything except clock.

3. **R4, R6–R9, R17, R36–R37:** Transactions are concurrent, with any `u64` id, including zero, and unlimited active count. Duplicate begin preserves the existing transaction; reused ended ids capture a fresh revision. Select the newest version at/before begin, then override with own writes. Tombstoned/expired selections never reveal older values. Expiry uses each call’s `now`, including old transactions; reads and predicates create no conflicts.

4. **R8–R13:** Expiry is strict: deadline equal to `now` is absent. `None` TTL clears an old deadline; positive TTL uses checked `now + d`; zero TTL writes a tombstone. Delete returns prior visible liveness but always writes a tombstone, even for never-existing keys. Every direct successful write adds one revision/version, including identical writes; staged rewrites occupy one slot. Count counts matching live entries, including empty values.

5. **R14–R17, R36:** Check all staged keys against committed heads, in String order, before committing anything; the first head newer than begin causes conflict regardless of equality, expiry, or tombstones. Conflict retains the entire transaction and original begin revision. Successful nonempty commit uses one shared new revision and preserves set-time deadlines. Empty commit returns current revision and ends the transaction; rollback discards only that transaction. Revision exhaustion is excluded.

6. **R18–R19, R21:** Validate snapshot names before lookup/capacity: empty means `NameEmpty`; otherwise ASCII lowercase first, then lowercase/digit/underscore, reporting the first invalid character’s UTF-8 byte offset. Three distinct names maximum; replacement succeeds at capacity. Snapshot copies only current committed live entries with absolute deadlines, even while transactions exist. Unknown valid restore/forget names return `SnapshotMissing`; restore lookup precedes `ActiveTransactions`, including read-only transactions.

7. **R19–R21:** Restore filters expiry from a copy without modifying the saved snapshot. Its union contains only currently committed live keys and still-live saved keys. Empty union creates no revision; otherwise append every union key at one new revision, using saved entries or tombstones, even for identical values. Expired/tombstone-only keys outside the union receive nothing. Forget removes only the registry entry.

8. **R22–R24, R38:** Scan/aggregate filters are inclusive start, exclusive end, and prefix, in String order. Empty start/prefix are valid; any supplied end `<= start` is invalid even for empty selections. Initial scan skips matching-key offset then takes limit without overflowing large arguments. Zero limit still validates range/cursor and yields no continuation. A nonempty page has a cursor exactly when another matching key remains.

9. **R24–R26:** Cursor start/end/prefix/offset must exactly match arguments, distinguishing `None` from `Some("")`; last must be nonempty and satisfy every filter. Validate even with zero limit. Last need not exist, and no store/transaction/revision binding applies. Resume strictly after last without reapplying offset; limit may change. Current visibility, later own writes, expiry, and subsequent direct commits can change results. Returned strings are owned.

10. **R27–R29:** Aggregate visits all matching live entries in key order, parsing then checked-adding each before advancing. Accept canonical ASCII i64 decimal only: `"0"` or optionally negative nonzero-leading digits, including `i64::MIN`; reject `"-0"`, plus signs, leading zeros, whitespace, Unicode digits, and out-of-range values. The earliest parse/add failure wins and identifies its original key/value as specified. Empty selection yields zero count/sum; zero values still count.

11. **R30–R31, R37:** GC retains each key’s head plus each active transaction’s selected committed version, deduplicated by version identity and kept in revision order. Read-only transactions and privately overwritten keys still pin versions; transactions predating a key pin nothing for it. Liveness never affects retention. Snapshots pin nothing. Return the exact removed-version count; preserve heads, staged writes, snapshots, begin revisions, and committed revision. No automatic GC occurs.

12. **R32–R34:** Stats distinguish version-bearing keys from current committed live keys. Count all retained historical versions/tombstones; expired values remain values, not tombstones. Exclude snapshot copies/private writes from those counts. Count all active/read-only transactions and distinct staged keys per transaction, including deletions/expired writes; snapshots count names. Clock equals admitted `now`; initial revision and all initial counts are zero.
