1. **R1–R2, R17:** Implement the exact time-taking API shown, including scan/aggregate; do not provide earlier-level signatures. Use one std-only file compiling under edition 2024, output in Rust fences, with no inner attributes/comments. All listed types, methods, fields and variants are public; Error, Cursor, Page and Aggregate require all four specified derives.

2. **R18–R19, R24, R34:** Every method except new first rejects backwards time, before any other check or purge. Otherwise admit now, then purge deadlines `<= now` from the visible map, even for depth or ultimately failing calls. Equal times are valid; the initial clock is zero. Later errors retain this clock advancement and purge; backwards calls change nothing.

3. **R2–R5, R13, R20:** After admission/purge, get/set/delete reject empty keys. Other characters and empty values are valid. Missing get returns None; missing delete returns false; count counts keys with exactly equal whole values, including empty values. set validates the key before checked deadline addition; overflow preserves any surviving old entry. None clears an old deadline; Some(0) immediately removes the key successfully. An exact `u64::MAX` deadline is valid.

4. **R3–R8, R21–R22, R24:** Writes affect only the visible map. begin copies it with absolute deadlines; four open scopes are allowed, and the fifth fails after admission/purge. commit replaces the entire parent map with the inner map, preserving deadlines; an outer rollback still undoes an inner commit. rollback discards one scope and immediately purges the newly exposed parent. NoTransaction follows admission/purge.

5. **R9–R11, R15–R16, R23:** Snapshots copy the complete visible map and absolute deadlines, never the scope stack. restore replaces only the visible map, preserves depth/parents, and purges the restored copy at now without modifying the saved snapshot. Registry changes survive all rollbacks. Three distinct names are allowed; replacement at capacity succeeds, forget frees capacity, and unknown valid restore/forget names return SnapshotMissing with the original name.

6. **R12, R16, R24:** Name validation follows admission/purge but precedes lookup or capacity checks. Empty names yield NameEmpty. The first character must be ASCII lowercase; later characters permit only ASCII lowercase, digits or underscore. Return NameInvalid at the UTF-8 byte offset of the first offending character, scanning left to right. Non-ASCII letters are invalid; names are compared exactly.

7. **R14, R16–R19, R24, R34:** Aside from admitted clock advancement and required expiry, every error preserves data, scope stack and snapshot registry. Purging never initially touches suspended maps or saved snapshots. Expired data cannot be recovered through a later backwards call. Stores share neither data nor clocks; there is no automatic commit or TTL renewal.

8. **R2, R25–R26:** scan/aggregate select live visible keys using all filters together: inclusive start, exclusive optional end, and optional starts_with prefix. Empty start/prefix are valid; None end is unbounded. Some(end) with `end <= start` is InvalidRange even when selection would be empty, and wins over cursor/numeric errors. Use ascending Rust String ordering without normalization, including non-ASCII keys.

9. **R27–R28:** Without a cursor, offset skips matching keys before taking limit. Huge offsets/limits must not overflow or panic. A nonempty page gets next exactly when another matching key remains; copy the request’s start/end/prefix/offset and the final returned key into it. Empty pages always have next None. A zero limit still validates range and cursor, then returns an empty page.

10. **R29–R30, R34:** A supplied cursor must exactly match start/end/prefix/offset, distinguishing None from Some(""). Its last must be nonempty and satisfy all requested filters, but need not currently exist or originate from this store. Resume strictly after last without reapplying offset; limit may change. Read the current map, so later keys may appear and deleted/expired last remains valid. Results and cursors own their strings.

11. **R31–R32:** aggregate counts every matching entry, including zero values; empty selection yields count zero and sum zero. Accept only canonical ASCII i64 decimal: “0”, or an optional minus followed by a nonzero digit and further digits. Reject “-0”, leading zeros, plus signs, whitespace, empty strings, non-ASCII digits and out-of-range values. Both i64 endpoints are valid; InvalidNumber carries the original key/value.

12. **R31–R34:** Process aggregate entries in ascending key order, parsing and then checked-adding each before examining the next. Invalid parsing yields InvalidNumber; addition overflow yields SumOverflow naming the causing key. The first encountered error wins, including an overflow before a later malformed value. Intermediate overflow fails even if later values would bring the mathematical total back into range; return no partial aggregate.
