1. **R1–R4, R19:** Expose every listed type, field, variant, and function exactly, with the required derives. Validate options first, including for empty patches: `max_offset≤16`, `fuzz≤2`. Options affect application only. Complete parsing before source validation or matching; any parse error beats any source or application error.

2. **R3–R7:** Only `""` is an empty patch. Every nonempty patch must first pass the final-LF check; failure is `BadHeader{line:1+LF_count}`, regardless of other syntax. Then check the exact file headers in order, reporting the first missing or unequal line. Headers without hunks yield `BadHunkHeader{line:3}`. Patch error lines are one-based physical lines.

3. **R8–R11:** Require the exact header spacing, punctuation, and all four fields. Each field independently allows only canonical ASCII decimal `0..=128`; reject signs, leading zeros, Unicode digits, and overflowing numerals as `BadHunkHeader`. A positive count requires a positive start. Convert positive-count starts by subtracting one; zero-count anchors remain unchanged.

4. **R12–R14:** Any physical line starting with `@@` terminates the current body and becomes the next header, even if malformed. Otherwise consume exactly one valid prefix; additional spaces or signs belong to the payload. Empty payloads are valid, unprefixed empty rows and CR are invalid. Validate all body rows before reporting count mismatch at the header.

5. **R14–R19:** For each hunk, check header, body validity, counts, presence of an edit, ordering, then the hunk limit. A count-correct context-only hunk—including an empty `0,0` hunk—is `BadBody` at its header. Earlier hunk failures beat later header failures. Accept 16 hunks; a valid seventeenth yields `TooLarge` after ordering checks, without validating subsequent hunks.

6. **R16–R17:** Order by nominal old full starts, requiring `current_start≥previous_start+previous_B`; adjacent ranges and repeated zero-length anchors are allowed. Independently require `new_start=old_start+Σ(previous_D−previous_B)` using signed arithmetic. Negative required new starts are invalid. Either violation produces `Misordered` at the current header.

7. **R4, R20–R21:** Validate source even for an identity patch: first the earliest CR’s UTF-8 byte offset, then missing final LF for nonempty source, then more than 128 lines. Empty source has zero lines; `"\n"` has one blank line. A terminating LF creates no additional line. Exactly 128 lines is allowed.

8. **R22–R25, R28:** Compute leading/trailing context runs from the original body. Independently allow `L≤min(fuzz,lead)` and `R≤min(fuzz,trail)`; never drop edits. Dropped context need not match but must exist. Every full candidate must satisfy `s+B≤working_length`, including fuzzed candidates; for `B=0`, both zero and end insertion positions are possible.

9. **R26–R28:** Compute signed `expected=nominal_old_start+net+drift`, initially with both accumulators zero. Do not clamp expected to source bounds. Include candidates at distance exactly `max_offset`, even when expected lies outside the source. Compare trimmed space/minus payloads exactly against `[s+L,s+B−R)`.

10. **R29–R32:** Rank all matching `(s,L,R)` choices lexicographically by `(L+R, absolute_distance)`; less fuzz wins before proximity. No match yields one-based `NoMatch`. Multiple distinct best starts yield `Ambiguous` containing the two smallest zero-based full starts. At one best start, choose smallest `L`; differing trims alone are not ambiguous.

11. **R24, R33–R34:** Replace only `[s+L,s+B−R)` using trimmed space/plus payloads in body order. Preserve actual dropped edge lines unchanged, including mismatching payloads. Check the resulting working length immediately: over 128 lines yields `TooLarge`, even if a later hunk would shrink it.

12. **R22, R35–R38:** After success, add `D−B` to net and set—not accumulate—`drift=s−(nominal_old_start+previous_net)`. Relocated hunks may revisit earlier working lines. Work privately and return only an error on failure. Preserve inputs, exclude file headers, and serialize every resulting line with one LF; zero lines produce `""`.
