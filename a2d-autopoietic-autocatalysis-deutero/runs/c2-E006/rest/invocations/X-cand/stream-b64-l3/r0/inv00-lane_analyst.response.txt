1. **R1–R2:** Deliver one std-only Rust source file compiling under edition 2024, inside `rust` fences, without inner attributes/comments. Match every public signature, variant, field, and required trait exactly; stream structs have private state, and `Default` is not required.

2. **R3, R13–R14, R25:** Use MSB-first six-bit digits and support all 256 input byte values. Accept nonzero unused tail bits (`Zh==` → `f`, `Zm9=` → `fo`). Accept only the selected alphabet; Standard and UrlSafe symbols are not aliases. Streams retain copied options.

3. **R4, R18, R26, R29:** Optional encoding pads exactly like Required; Forbidden omits padding. Encode zero tail bits. Padding counts toward wrapping width; separators appear only between nonempty rows, never before the first or after the last. Empty input produces nothing.

4. **R5–R9, R12, R16:** Scan left to right without length or character prevalidation. For each non-skipped symbol, precedence is completed padded group → pending second `=` → illegal `=` placement → invalid byte. Thus invalid bytes after padding or after a pending position-two `=` produce `BadPadding`, not `InvalidByte`.

5. **R6–R8, R10–R11, R16:** Positions are zero-based within each four-symbol group. `=` at positions 0/1 fails immediately; at position 2 it waits for another `=`. At EOF, that pending `=` gives `BadPadding` at its own offset. Otherwise Required gives `Truncated` at the incomplete group’s first symbol, not EOF.

6. **R12, R24, R26:** Forbidden rejects every `=` immediately with `BadPadding`, subject to existing terminal/pending precedence. Optional and Forbidden accept two- or three-digit residual groups only at EOF; one digit is `Truncated`. Optional still requires any started padding to be complete. Scan errors always beat EOF errors.

7. **R9, R20, R27, R32:** IgnoreAscii skips exactly bytes 9–13 and 32, anywhere—even between `==` or after completed padding. None skips nothing; other bytes, including `0x85` and UTF-8 bytes, undergo symbol checks. Every offset counts physical bytes, including skipped bytes and earlier pushes.

8. **R17, R28:** Both constructors and both one-shot functions validate Wrapped width before inspecting input, including empty or malformed input. Valid widths are exactly multiples of four from 4 through 120 inclusive; zero, values outside that range, and other multiples fail with the original width.

9. **R29–R30:** Wrapped decoding permits EOF after a short final row or exactly at width. Continuing beyond width requires the selected separator; separators before width are forbidden. Wrong/missing separators and ASCII whitespace inside rows give `BadWrap` at the first offending byte.

10. **R30–R32:** Framing runs before padding/alphabet checks, even after terminal padding. CRLF may span pushes: wrong byte after CR errors there; EOF after CR errors at CR. EOF after a complete separator errors at its first byte. These EOF framing errors precede padding/truncation errors.

11. **R15, R17–R21, R24:** Open empty pushes succeed without disturbing buffers. Encoder pushes emit all complete triples; decoder pushes emit only completed four-symbol groups, including padded groups immediately. Finish emits permitted tails. A failing decoder push returns no output from that call; earlier successful outputs remain. Chunking must preserve results and first-error offsets.

12. **R22–R23:** Successful finish closes either stream; every later operation, including empty push, returns `AlreadyFinished`. Every decoder error is sticky, including finish errors and `AlreadyFinished`: later operations return the identical error without scanning or advancing. Completing padded data alone does not close the decoder; extra symbols before finish still undergo framing and terminal-padding checks.
