1. **R1–R2:** Submit one Rust source file in a single `rust` fence, compatible with `rustc --edition 2024`, using only `std` and no inner attributes/doc comments. Preserve the exact public API, fields, variants, and required derives; helpers may be private.

2. **R3–R5:** Check raw emptiness first, then the first non-ASCII byte anywhere, before all syntax checks. Never trim whitespace or remove comments. Every `at` is an original-input byte offset; an absent end position uses `input.len()`, while a removed root dot retains its original position.

3. **R6:** Only a quote at byte zero starts protection. Find the first unescaped closing quote, treating every backslash plus following byte as skipped regardless of escape legality. Missing closure, including a trailing backslash, yields `UnclosedQuote` at the opening quote before separator checks.

4. **R7, R21:** Ignore everything through the quoted prefix’s closing quote when counting separators; quotes elsewhere protect nothing. Zero separators gives `MissingAt`; multiple separators gives `MultipleAt` at the second, before any local/domain errors. With exactly one, an empty local reports its separator first.

5. **R8–R9:** Unquoted length above 64 wins over all content errors, at byte 65. Otherwise scan left-to-right using exactly the specified character set. Leading/trailing dots fail at themselves; consecutive dots fail at the second, unless an earlier invalid byte already wins. Preserve local spelling and case.

6. **R10–R11:** For quoted locals, any byte between closing quote and separator yields `TrailingLocal` at the first such byte before decoding. Decode left-to-right: ordinary bytes allow exactly `0x20..=0x7e`; only `\"`, `\\`, and `\@` are valid escapes. Unsupported escapes report their backslash.

7. **R11–R12:** Complete quoted content validation before checking decoded emptiness or length, so even a late content error beats excess length. Empty decoding reports the closing quote; over 64 decoded bytes reports the origin of decoded byte 65, using the backslash for escapes. Quoted locals have no dot-atom restrictions.

8. **R13–R14, R21:** Validate the domain only after local success. Remove exactly one terminal dot, then check emptiness, then the 253-byte limit; excess length reports byte 254 before label errors. The removed dot does not count. For `a@.` emptiness points at that dot; for `a@` it points at `input.len()`.

9. **R15–R16:** Preserve empty labels and validate each label completely before proceeding. Empty-label positions are the leading dot, second dot of an interior pair, or removed root dot for an empty final label. Thus `a@b..` still fails after removing one terminal dot. Nonempty labels above 63 bytes report byte 64 before content checks.

10. **R17–R18:** Within each length-valid label, check leading hyphen, then trailing hyphen, then characters left-to-right. Either boundary hyphen beats an interior invalid character; leading wins when both apply. Content permits only ASCII letters, digits, and hyphens, excluding underscores and bracketed literals.

11. **R19–R20:** Only after every label succeeds, require at least two labels, reporting `DomainNeedsDot` at domain start. This beats numeric-TLD checking: `a@123` fails for missing dot. An all-digit final label then yields `NumericTld` at its start; mixed digits/letters and valid hyphens are allowed.

12. **R12, R20–R21:** Success returns decoded quoted local or unchanged unquoted local, the correct `quoted` flag, and an ASCII-lowercased domain without its root marker. Exactly 64 local bytes, 63 label bytes, and 253 domain bytes are allowed. Impose no additional total-address limit, DNS lookup, IDNA conversion, or Unicode processing.
