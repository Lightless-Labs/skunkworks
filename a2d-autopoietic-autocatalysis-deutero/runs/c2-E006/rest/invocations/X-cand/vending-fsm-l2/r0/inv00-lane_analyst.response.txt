1. **R1–R2:** Deliver one std-only Rust source file in a single `rust` fence, compatible with edition 2024, without inner attributes/comments. Match every API name, type and visibility exactly; Machine fields stay private. All other listed types require Clone, Debug, PartialEq and Eq.

2. **R5–R8:** Constructor validation is ordered: empty catalog first; then products in input order, checking ID syntax → duplicate → price for each. IDs contain exactly 1–8 lowercase ASCII letters; prices include both 1 and 100. Return the first error with the entire offending ID; a duplicate beats its invalid price.

3. **R3, R22:** Validate tubes only after every product passes. Counts 0 and 100 are valid; scan indices `[1,3,4,10]` and report the denomination of the first count above 100, not its index or count.

4. **R4, R9, R20–R21:** Initialize zero credit, no selection, empty escrow and exactly the supplied tubes. Machines, snapshots and receipts own independent data. Preserve exact ID bytes and escrow insertion order; catalog data is immutable, stock unlimited, and operations cause no undocumented automatic actions.

5. **R3, R10–R11:** Insert accepts only 1, 3, 4 and 10. Check denomination before credit limit, so an invalid coin always yields BadCoin. Credit exactly 100 is valid; rejected insertion changes nothing. Handle every u16 input without wrapping or panicking; insertion remains allowed with a selection.

6. **R6, R12–R13:** Select performs exact, case-sensitive membership lookup without syntax validation or normalization; unknown strings produce UnknownProduct carrying the supplied string. Only then check SameSelection, even at zero credit. Success replaces selection without touching money; failure preserves the previous selection.

7. **R14–R15, R19, R26, R28:** Vend error precedence is NoSelection → Underpaid → NoChange → TubeLimit. Selected with zero credit means Underpaid. Every Err from every method preserves all state and reports pre-call values; result-returning methods must never panic. Failed vending leaves the machine usable for further insertion, selection or refund.

8. **R17, R23, R25:** Compute change as credit minus price using only pre-vend tubes. Greedy visits 10, 4, 3, 1 and takes the maximum permitted at each step, including exact boundaries. If it succeeds, its exact descending vector is mandatory despite any shorter alternative; zero change is empty.

9. **R24–R25:** Only greedy failure triggers fallback. Discard all tentative greedy withdrawals and search original tube counts for exact change. Minimize coin count, then choose the lexicographically greatest descending integer vector among ties. Return NoChange with the full owed amount if none exists.

10. **R22, R26:** After fixing the change vector, subtract it from original tubes, then add every escrow coin. Check final proposed counts against 100 in ascending denomination order. Do not reject based on an intermediate count or try another change combination to avoid overflow; even zero-change sales need this check.

11. **R16, R27:** Successful vend returns the selected ID, its catalog price and chosen change, commits the proposed tubes, and clears selection, escrow and credit. Withdrawal and escrow deposit form one atomic update; insert itself never deposits into tubes.

12. **R18, R21:** Refund always succeeds, including with no credit: return all escrow coins in reverse insertion order, then clear credit, escrow and selection. It neither reads nor modifies tubes, and its returned vector remains independent of subsequent operations.
