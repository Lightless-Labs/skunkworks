1. **R1–R4, R17, R21–R27, R30:** Preserve every specified public signature. `parse` is associated; other operations borrow operands. `Big`’s representation is private; both types implement all four required traits. Use exactly the specified error variants. Submit one std-only Rust 2024 file in Rust fences, without `main`, inner attributes, or inner documentation.

2. **R5–R8, R10:** Only one ASCII sign at byte 0 is special. `""` is `Empty`; `"+"` and `"-"` are `SignOnly`; `"++"` is `InvalidDigit { index: 1 }`. Never trim. All indexed errors use original UTF-8 byte offsets, including the sign; a non-ASCII character fails at its first byte.

3. **R9–R14:** Apply the complete precedence: `Empty → SignOnly → InvalidDigit → Separator → LeadingZero → TooManyDigits`. Scan the entire magnitude for invalid bytes before checking separators, regardless of the limit. For example, `"_x"` reports invalid byte 1, not separator 0.

4. **R9–R11:** An underscore requires immediately adjacent ASCII digits on both sides within the magnitude. Leading, trailing, and doubled underscores fail at the leftmost malformed underscore: `"1__2"` reports index 1. A sign cannot serve as an adjacent digit.

5. **R12–R14:** After separator validation, multiple magnitude digits beginning with zero always produce `LeadingZero` at the first digit, even when the limit is exceeded. Thus `"-0_1"` reports index 1; `"0_0"` is invalid, while `"0"`, `"+0"`, and `"-0"` pass this check.

6. **R13–R15:** Count only digits; report the original byte position of the first digit beyond the call’s limit. Zero consumes one digit, so limit 0 rejects `"0"`. Limits are independent across calls. Handle `usize::MAX` without overflowing expressions such as `max_digits + 1`.

7. **R2, R15–R16, R24, R28:** Values and intermediates must support arbitrary precision; fixed machine integers or hidden digit caps are insufficient. Equality is numerical, independent of spelling or parse limit. Every route to zero must equal parsed `"0"` and erase any negative sign.

8. **R17–R18, R20:** Format the absolute value without unnecessary zeros, then pad to at least `min_digits`; never truncate. Zero has at least one digit even at width 0. Prefix only negative values with `-`; never emit `+`. Padded output need not be parseable.

9. **R19–R20:** Group after padding, counting magnitude digits from the right; the sign is outside grouping. Group 0 disables separators, group 1 separates every digit, and a group at least as large as the padded magnitude adds none. Handle `group = usize::MAX` without arithmetic overflow.

10. **R21–R24, R29:** Comparison must handle equality and all signs, reversing magnitude order for two negatives. Addition and subtraction require full carry/borrow propagation and signed results; subtracting a negative adds its magnitude. Every operation leaves both operands unchanged and retains no parse limit or spelling.

11. **R25–R29:** Negation and multiplication must handle every sign combination; two negatives multiply to a positive. `signum` returns exactly `-1`, `0`, or `1`. Cancellation, negated zero, and zero multiplied by either sign all produce canonical zero; multiplication intermediates must not overflow.

12. **R30–R33:** Check numerical divisor zero first, including `0/0`, and return `DivisionByZero` without panicking. Otherwise return `(quotient, remainder)` with truncation toward zero, `self = q*rhs + r`, and `|r| < |rhs|`; nonzero remainder follows the dividend’s sign. Smaller dividend magnitude gives `(0,self)`; equal magnitudes give quotient `±1` and zero remainder.
