1. **R1–R2:** Deliver one std-only Rust source file in `rust` fences, compiling under edition 2024. Preserve the exact public API, field and variant names/types, and all four required derives; add no public callable API.

2. **R3–R5:** Validate in this exact precedence: zero width, width above 256, first indent ≥ width, rest indent ≥ width, cost above 1,000,000. Width 256, zero indents, and costs 0 and 1,000,000 are valid. Reject even `usize::MAX` values before subtraction or squaring; validated layout arithmetic is bounded.

3. **R6–R7:** After configuration validation, scan the entire original input for controls before checking any markers. The earliest forbidden control wins even over an earlier malformed marker. Allow tab/CR/LF; report original UTF-8 byte offsets, not scalar positions or normalized offsets.

4. **R7, R9:** Validate every ASCII `~` using its immediately adjacent original scalars: both must exist and be neither markers nor separators. In `ab~~cd`, report the first marker. Only space, tab, LF, CR, and NBSP are separators; other Unicode characters can validly neighbor markers.

5. **R8–R11:** Normalize CRLF to one LF, then remaining CR to LF. Each maximal adjacent LF run of length n ≥ 2 contributes exactly n−1 empty strings, including at input edges. Spaces/tab/NBSP between LFs prevent a boundary; a single LF merely separates words.

6. **R11–R13, R24:** Empty input and separator-only segments yield no content lines, but preserve boundary empty strings without indentation. Collapse separators to word boundaries, remove markers, and preserve other scalars literally. Each segment resets first-line indentation; widths count scalars, including indentation, not bytes or display cells.

7. **R14–R15, R20:** Always try the entire remaining displayed suffix first, reserving exactly one separating space when the line already has content. An exact fit wins over every marker opportunity. Literal hyphens offer no break opportunities.

8. **R15–R17:** A usable marker lies strictly after the current consumed offset and before the word’s end; its displayed prefix plus an added ASCII hyphen must fit, including any separating space. Choose the rightmost usable marker first, not the cheapest one. On an empty line, always accept it regardless of cost.

9. **R16, R18:** On an occupied line, accept that rightmost opportunity only when U² + cost < (C−L)², where C excludes indentation and L is existing content length. U includes the space and hyphen just added; the baseline reserves no space. Equality, rejection, or no opportunity means flush and retry unchanged, without trying an earlier marker or raw-splitting there.

10. **R17, R19–R20:** Accepted hyphen breaks emit immediately and resume after the marker. Only an empty line without a usable opportunity may raw-split an oversized suffix into C displayed scalars, adding no hyphen and discarding passed markers. Recompute capacity for subsequent lines; exact completion never creates an extra empty line.

11. **R21, R23–R24:** Select all paragraph lines before justification. Justify only nonfinal lines containing at least two word pieces, counting a hyphen prefix after a prior word as another piece with one gap. Indentation is never a gap; continuations start without one. Final and one-piece lines receive no right padding; all output lacks trailing spaces and embedded CR/LF.

12. **R22:** Compute extra spaces from the line’s scalar width including indentation and its existing single gap spaces. Add floor(E/G) to every gap, then distribute the remainder cyclically starting at gap `paragraph_line_index % G`, wrapping left to right. The index counts every content line, including raw/hyphen splits, and resets per paragraph; boundary strings do not count.
