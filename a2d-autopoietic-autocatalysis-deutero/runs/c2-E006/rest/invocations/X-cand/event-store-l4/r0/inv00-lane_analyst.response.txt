1. **R1–R6, R20:** Deliver one std-only Rust 2024 source file in `rust` fences, with no inner attributes/comments. Match every R2 signature, public field and required trait; keep Store/Projection internals private. Empty replay returns exactly `New/0/0/0`; process events in order, stop at the first error with a zero-based index, and count every success, including identical events, Open and Close.

2. **R7–R15:** Preserve event-check precedence: Open validates limit `1..=1_000_000_000` before checking New status; both Open and Closed yield AlreadyOpened afterward. Deposit checks lifecycle → positive amount → capacity. Withdraw checks lifecycle → positive amount → floor `0..=limit` → sufficient funds → resulting balance ≥ floor. Equality succeeds at each inclusive bound; handle `i64::MAX` safely. Withdraw’s floor is never stored.

3. **R4, R16–R19:** Close checks lifecycle → expected version → zero balance, so version mismatch wins over NonZeroBalance. Compare against the pre-event stream version and report the event’s expected value and current actual value. Successful Close increments version, preserves limit and zero balance, and is permanent. Returning to zero never resets version; only Open can successfully initialize an account.

4. **R21, R36, R41, R47:** Validate IDs before lookup or other checks, including read accessors. Length is 1–24 UTF-8 **bytes**; byte 0 must be ASCII lowercase, later bytes lowercase/digit/hyphen. Empty reports byte 0; otherwise report the earliest invalid byte before index 24, or index 24 for excessive length. Non-ASCII bytes are invalid. Projection ingest also reports the call-local record index.

5. **R22–R25:** append validates ID → Expected → events, even for empty batches. Missing matches absence only; Exact(0) does not match absence. Conflict preserves the supplied Expected and uses `None` for absent actual. Validate against the existing account and commit atomically; any failure leaves the entire Store unchanged. Rejection indices are batch-local. Empty success returns the current/initial account without creating a stream.

6. **R26–R30, R36:** Distinguish absent (`None`) from present with no matching events (`Some(empty)`). history filters one-based stream versions strictly greater than `after`, retaining full history forever. Only interval zero is invalid. Snapshot boundaries count every successful event per stream; capture the greatest positive divisible version, including intermediate batch states. tail starts strictly after that snapshot, or contains full history without one. Empty/rejected appends change neither.

7. **R31, R33–R34:** Validate supplied snapshots before examining tails: zero version → InvalidVersion; then structural InvalidState; then TagMismatch. Reject New, invalid limit/balance, and Closed with nonzero balance or version below 2. Do not demand historical reachability or interval alignment: Open/version 1/positive balance is valid. Empty-tail rebuild returns the validated account exactly; tail error indices start at zero.

8. **R32–R35:** `snapshot_tag` validates nothing: use `version.rotate_left(7) ^ (limit as u64).wrapping_mul(31) ^ (balance as u64).rotate_left(17) ^ status_code`, with New=0, Open=0xA5, Closed=0x5A and Rust cast semantics. Rebuild without a snapshot wraps replay errors as Tail. With a valid snapshot, version overflow precedes every event check: MAX−1 may advance once to MAX; the following event fails.

9. **R37–R38:** Each committed event produces exactly one Record with contiguous one-based **global** position and one-based **stream** version, exact ID and cloned event. Preserve batch order across streams. Failed/empty appends and snapshots consume no positions. records filters strictly above `after` in increasing position order; `u64::MAX` returns empty. Respect the stated storage/count assumptions without wrapping arithmetic.

10. **R39–R41, R43–R45:** Projection starts empty with position/totals zero and accepts arbitrary record sources. Process provisionally left to right, but roll back the entire call on any error. Check each record in this order: ID → nonzero position → duplicate handling or global contiguity → stream version → event. Errors use call-local indices; later checks cannot override earlier failures.

11. **R42, R46:** A position at or below the provisional cursor is a duplicate attempt: compare **every Record field** against the journal entry there. Exact matches skip event/version validation; differences yield DuplicateMismatch. Duplicates may arrive out of order or refer to records newly accepted earlier in this call. Return only the number of new records; empty and duplicate-only calls change nothing.

12. **R20, R27, R36, R47–R50:** Preserve immutable inputs and independent owned returns/clones. Store equality includes history and configuration; Projection equality includes journal, cursor and accounts. State must agree with full replay and snapshot-plus-tail rebuild. Projection uses stream versions for Close, retains closed accounts, and totals count all streams, Open/Closed separately, with balance summed as `i128`; no successfully projected account remains New.
