1. **R1–R4, R38:** Use the exact public API, variant fields, and required derives; private helpers are allowed. Deliver one std-only Rust 2024 source file in Rust fences, without inner attributes/docs or a required `main`. Preserve literals byte-for-byte; empty input returns `Ok("")`. All failures return `Err`, without mutation, shared state, or panics.

2. **R4–R7:** Positions are UTF-8 **byte** offsets. Validate the entire template before accessing values; any syntax error beats every value error. Scan left to right: outside `}` errors immediately; for `{`, first seek the next `}`. If absent, report `Unclosed` at the opening even if another `{` follows; otherwise the first inner `{` wins over all content checks.

3. **R8–R9, R11:** Consume at most one leading operator. All seven recognized operators are supported, so these rules provide no reachable `UnsupportedOperator` case. Other punctuation enters name validation. Operator-only content gives `EmptyExpression` at `}`; otherwise preserve comma-separated empty entries and report `EmptyVariable` at the entry start, including `}` for a trailing entry.

4. **R10–R11, R21–R22:** Split each specifier at its first `*` or `:`. Validate the name first, then the entire modifier, then expression-local duplication, before proceeding to the next specifier. Names use only the specified ASCII grammar; whitespace stays significant, and non-ASCII errors point to its first byte. Empty names error at specifier start. Duplicate names error there too.

5. **R21–R22:** The only valid suffixes are exactly `*` or `:n` with 1–4 ASCII digits, starting `1`–`9` (inclusive range 1–9999). Zero, leading zeros, signs, extra punctuation, repeated/mixed modifiers, or trailing text produce `InvalidModifier` at the **first modifier punctuation**, not where the suffix becomes invalid.

6. **R12, R25–R27, R31:** Select the last exact matching binding before validating its value; even an empty last value shadows earlier ones. Ignore unused bindings and their names. Missing variables with valid modifiers contribute nothing. Process selected values in specifier order; the first value error wins. Collection-prefix `TypeMismatch` precedes duplicate-map-key checking.

7. **R13–R14, R16, R36:** Encode UTF-8 bytes with uppercase `%HH`; preserve only unreserved ASCII, plus the specified reserved set for `+`/`#`. Greedily preserve existing ASCII-hex triplets while uppercasing their digits, without decoding—even `%41` and `%25`. Invalid `%` becomes `%25`; following bytes are processed normally. Collection separators remain literal, even when reserved data makes output ambiguous.

8. **R23–R26:** Scalar explode is a no-op under every operator. Prefix slicing counts Unicode scalar values before encoding or triplet recognition; oversized prefixes retain the whole scalar. Thus `%2fX` with `:2` becomes `%252`, with `:3` becomes `%2F`. Prefixing any present list/map errors, including empty collections.

9. **R15, R17–R20, R37:** Prefixes and separators depend on contributed **field count**, never rendered length. Empty scalars contribute fields; absent variables and empty collections do not. Simple/`+` use commas without prefixes; `#`, `.`, `/`, `;`, `?`, `&` emit their specified prefix once per nonempty expression. Adjacent expressions act independently, including repeated `?` or `#`.

10. **R19–R20, R28–R30:** Preserve list order, repetitions, and empty items. Nonexploded nonempty lists form one field from individually encoded items joined by literal commas; exploded lists form one field per item. For `;`, `?`, `&`, use the original variable name on each applicable field: `;` omits `=` for an empty value, while `?`/`&` retain it.

11. **R31–R33:** Maps retain vector order. Reject duplicate **raw**, case-sensitive keys—even if values differ—with `DuplicateKey` at specifier start; empty keys are valid. Encode keys/values independently. Nonexploded nonempty maps form one comma-flattened `key,value,...` field, wrapped with the variable name for `;`, `?`, `&`. Empty maps contribute no fields.

12. **R34–R37:** Exploded maps omit the original variable name under every operator. Each entry becomes `encoded_key=encoded_value`, retaining `=` even for empty components, except `;` omits `=` when the value is empty. An empty-key/empty-value entry still contributes one field; under `;` its empty rendering still triggers the prefix and participates in separators.
