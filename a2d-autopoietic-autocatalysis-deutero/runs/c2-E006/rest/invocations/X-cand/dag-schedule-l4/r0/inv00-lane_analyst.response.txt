1. **R1–R3, R20, R29:** Deliver one std-only Rust 2024 source file in Rust fences, without inner attributes/comments. Match every public declaration, field, variant, type and required trait exactly. Calls must be independent and deterministic, preserve inputs, use no I/O, and return owned outputs.

2. **R4, R44:** Validate every dependency before checking anything else, scanning task IDs ascending and entries left to right. At each entry check out-of-range, then self-reference, then duplication within that list; return immediately with original indices/values. Cross-list repetition is legal; silently deduplicating is not.

3. **R8, R21–R25, R38:** The pipeline is dependencies → worker count → resources → cycles → tails → simulation. Require 1–64 workers even for empty tasks. Resource validation is task-by-task: check shape first, then demands by ascending resource index. An earlier excessive demand beats a later shape error; cyclic and zero-duration tasks still require validation.

4. **R5–R7:** Kahn traversal must always remove the smallest *currently* available ID, including newly unblocked smaller IDs. On failure, report every unremoved ID ascending, including acyclic descendants blocked by cycles, excluding removed tasks. Zero-duration cycles count, and cycles beat all arithmetic errors.

5. **R9–R10, R38–R39, R43:** Compute tails in reverse of that exact Kahn order: duration plus maximum immediate-successor tail, or duration for a sink. Ignore release, priority, resources, workers and cooldowns. Use checked addition and return the first overflow encountered in reverse Kahn order, regardless of releases.

6. **R10–R12, R27, R39, R41, R43:** Eligibility requires an unstarted task, release ≤ current time, and every predecessor completed. Filter eligible tasks by current resource fit, then rank by descending tail, descending signed priority, ascending ID. Support i32 extrema without unsafe negation. Bypass nonfitting tasks, never reserve for future tasks, and never preempt.

7. **R13, R16, R36–R37:** Begin at time 0. Process all existing completions at a time in ascending task ID before any starts, releasing each task’s resources. Admit one task and reevaluate; a newly started zero-duration task completes immediately with adjacent start/end lines before another admission, potentially unblocking a new highest-ranked task.

8. **R15, R21, R28, R37, R42:** Select the task before selecting its worker. Scan cyclically from task ID modulo worker count and choose the first available worker, even if a lower ID is free. Availability begins at finish + cooldown; initially all workers are available. Never prefer a shorter cooldown or avoid the selected worker’s overflow.

9. **R7, R14, R18–R19:** For each admission, check start + duration first, then finish + assigned cooldown; report Finish before Turnaround. Check both even for zero-duration and final tasks. Exact u64::MAX is valid; wrapping, saturation and sentinel collisions are incorrect. The first failing admission returns an error without a partial schedule.

10. **R22, R25–R27, R32, R40–R41:** Resources are independent reusable capacities, including zero and u32::MAX; empty capacity is legal. Reserve all demands atomically and release them at finish, before cooldown ends. Fit and snapshots must use exact arithmetic without overflowing intermediate demand sums. All-zero demands fit even when positive resources are exhausted.

11. **R17–R19, R35, R43:** Keep admitting while a worker and fitting eligible task exist; otherwise advance to the earliest strictly later finish, unstarted release or cooldown expiry. Handle events at u64::MAX without incrementing time. Return runs in input-ID order and makespan as maximum actual finish, excluding cooldown; empty tasks produce empty runs and makespan 0.

12. **R29–R36:** Trace must be exactly `workers=W;resources=R\n`, then chronological `T|start|I|W|U\n` / `T|end|I|W|U\n` lines, then `makespan=M\n`. Each U is aggregate usage after that individual reservation/release; simultaneous ends have successive snapshots. Print every resource count, including zeros, comma-separated, or `-` for no types; use plain decimal, no spaces or extra lines, and one final LF. Empty tasks have only header and footer.
