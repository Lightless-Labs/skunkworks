1. **R1:** Preserve every public type, field, variant, signature, and required derive exactly. Calls must leave `jobs` unchanged and share no state; IDs `0` and `u32::MAX` are valid.

2. **R2–R5:** Validate before simulation, including for empty input: quantum first, switch cost second, job count third. Accept quantum `1..=1000`, switch cost `0..=1000`, and exactly 64 jobs; reject values outside those bounds.

3. **R6–R7:** Validate rows in input order, checking duplicate ID before ticks at each row. A duplicate beats invalid ticks on the same row, but an earlier row’s invalid ticks beat a later duplicate. Ticks `0` and `1000` are valid.

4. **R8–R10:** Start at time zero with every input index queued, including zero-tick jobs. Pop the head, consume `min(quantum, remaining)` for positive work, and append only unfinished jobs to the tail; never reorder by ID or remaining work.

5. **R11, R18:** Zero-tick jobs complete when actually popped, not automatically at time zero. They create no Run, consume no time, and may complete after earlier positive work.

6. **R12–R14:** Remember the last positive dispatch’s ID even after that job finishes. Zero-tick removals neither replace nor clear it; use an explicit absence state because every `u32` ID is valid.

7. **R13–R15:** Immediately before each positive dispatch, charge switch cost exactly when its ID differs from the remembered ID. The first positive dispatch and consecutive dispatches of the same ID are free; a finished predecessor does not waive a switch.

8. **R15–R16:** Switching produces only a time gap, never a Run. Emit exactly one Run per positive dispatch, preserving dispatch order even when adjacent Runs have the same ID or touch with no gap.

9. **R9, R17:** Dispatches run without interruption. Set start after any switch cost, end to start plus consumed ticks, and finished exactly when remaining work reaches zero—including when remaining work equals quantum.

10. **R18–R19:** Record positive-job completion at its final Run’s end, before any later switch cost. Return exactly one completion per input job in input order; preserve that order for equal completion times too.

11. **R15, R20:** End is the clock when the queue becomes empty. Charge no trailing switch cost, including before trailing zero-tick removals; those removals retain the existing clock.

12. **R20–R21:** Valid empty input returns both vectors empty and end zero; all-zero input returns no Runs, input-ordered completions all at zero, and end zero. Use exact `u64` time arithmetic throughout, including maximum workloads and switch costs.
