1. **R1:** Preserve every listed public type, field, signature, and derive; use one source file, Rust edition 2024, and std only. Do not mutate jobs. IDs 0 and `u32::MAX` are valid, so neither can represent “no previous dispatch.”

2. **R2–R5:** Validate before simulation, strictly in this order: quantum, switch cost, job count. Quantum accepts 1 and 1000 but rejects 0; switch cost accepts 0 and 1000; 64 jobs is valid. Empty input still undergoes parameter validation.

3. **R6–R8:** Validate rows in input order, checking duplicate ID, arrival, then ticks within each row. Report the offending row’s zero-based index. An earlier row’s error beats every later error; arrival and ticks both accept 0 and 1000.

4. **R9, R11–R12:** Start at time 0 and admit events by `(arrival, input index)`, never by ID. Admit all events with timestamp ≤ current time before selection; append positive-work arrivals behind jobs already waiting.

5. **R10, R12, R19:** Zero-tick jobs complete at their original arrival timestamp even when admitted later during execution or dispatch cost. They create no Run, enter no ready queue, and never change the last dispatched ID.

6. **R13–R15:** Remove and lock the selected queue head before charging cost. Arrivals during cost cannot replace it. Charge exactly one switch cost when a previous positive-work dispatch exists with a different ID; the first dispatch is free. Admit events through the cost’s end before execution.

7. **R15–R16, R18:** Execute uninterrupted for exactly `min(remaining, quantum)` CPU ticks; dispatch cost consumes none of the quantum. Emit one Run per dispatch, starting after cost. Never merge Runs; exact quantum multiples finish without an extra dispatch.

8. **R17–R18:** Admit every arrival through Run.end—including arrivals exactly at that boundary—before appending an unfinished running job. These arrivals therefore precede its requeued entry. Set `finished` precisely when remaining work becomes zero.

9. **R14, R19–R20:** Remember the executed job’s ID even after it finishes. Repeated dispatches of that ID are free; switching to another ID costs time even if the previous job finished. Clear this memory only when time advances through positive idle.

10. **R20–R21:** With an empty ready queue, advance to the next pending event, including a zero-work event. Record only positive skipped intervals as idle, merge touching intervals, and exclude dispatch costs. Successive zero-work events can split advances that must merge into one idle interval.

11. **R10, R21–R23:** Continue until every job completes, including future zero-work jobs after the final Run. `end` is the latest completion time; initial idle starts at 0, and none follows the last completion. Completion entries appear exactly once per job in input order. Valid empty input returns empty vectors and end 0.

12. **R16, R21, R24:** Runs and idle intervals are half-open `[start,end)`. Perform time and statistics arithmetic exactly in `u64`, including dispatch-cost accumulation. Results must be deterministic and independent across calls, without external state or services.
