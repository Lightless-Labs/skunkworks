1. **R1–R2, R17:** Deliver one std-only Rust source file inside `rust` fences, compiling with edition 2024; no inner attributes or inner doc comments. Use exactly the supplied time-taking API, public fields/variants/items, and required derives. No separate level-1 API is needed.

2. **R17–R19, R24:** Every method except `new` first checks time, including reads and invalid calls. Backwards time wins over every other error and changes nothing. Otherwise admit `now`, then purge the visible map, then perform method-specific validation. Equal times succeed; a later error still advances the clock.

3. **R14, R18–R19, R24:** After admission and initial expiry, errors must leave data, scopes, and snapshots unchanged. They do not reverse admitted time or expiry. A later backwards call cannot resurrect purged entries. Stores share neither data nor clocks.

4. **R2–R5, R13:** Only an empty key is invalid; whitespace, Unicode, and other characters are allowed. Missing nonempty keys yield `None` or `false`. Values may be empty; `count("")` is valid and counts matching keys, using exact whole-string equality without normalization.

5. **R19–R20:** Expiry means `deadline <= now`, including equality, and occurs before key validation or presence checks. Thus deleting an expired key returns `false`. Even `depth`, invalid requests, and calls returning errors purge the current visible map; suspended maps and snapshots remain untouched.

6. **R13, R20:** For `set`, validate the key before checked deadline addition, so `KeyEmpty` beats `DeadlineOverflow`. `Some(0)` removes the key successfully even when absent; `None` clears any previous deadline. Overflow preserves a still-live old entry. At `u64::MAX`, zero TTL succeeds, positive TTL overflows, and permanent entries remain live.

7. **R3–R4, R6, R21:** Reads, writes, deletes, counts, and snapshot creation use only the innermost map, or committed data when depth is zero. `begin` copies that complete live map with unchanged absolute deadlines. Four open scopes are allowed; the fifth returns `DepthLimit` after admission/purge without pushing a scope.

8. **R7, R21, R24:** `commit` checks `NoTransaction` after admission/purge. Success pops exactly one scope and replaces the parent’s entire map, preserving deletions and deadlines; it does not merge maps. An inner commit remains subject to a later outer rollback.

9. **R8, R15, R22, R24:** `rollback` likewise checks `NoTransaction` after admission/purge, then discards exactly one scope and immediately purges the exposed parent at the same `now`. It restores surviving original deadlines, never expired originals, and never undoes snapshot-registry changes.

10. **R12, R16, R24:** For all three named operations, validate after admission/purge but before lookup or capacity checks. Empty means `NameEmpty`; otherwise require `[a-z][a-z0-9_]*`. Report the first invalid character’s UTF-8 byte offset, not character index; uppercase, non-ASCII characters, and initial digits/underscores are invalid.

11. **R9–R11, R15, R23:** Snapshots copy the complete visible map and absolute deadlines, never stack/depth. Restore replaces only the visible map and immediately purges the copy; it preserves parent maps, depth, and the saved snapshot. Restores neither renew TTLs nor alias saved data. Unknown valid names yield `SnapshotMissing` containing the exact input.

12. **R8–R9, R11, R15–R16:** Three distinct snapshot names are allowed, including snapshots of empty maps. Replacing an existing name succeeds at capacity; a fourth distinct valid name returns `SnapshotLimit`. Forget removes only the registry entry and frees a slot. Creation, replacement, and forgetting persist through commits and rollbacks; all behavior must be deterministic.
