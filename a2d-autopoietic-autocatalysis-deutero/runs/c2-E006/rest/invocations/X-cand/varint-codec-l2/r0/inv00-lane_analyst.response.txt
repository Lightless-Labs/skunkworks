1. **R1–R3:** Deliver one std-only Rust source file in a `rust` fence, compiling under edition 2024, with no inner attributes or inner doc comments. Preserve every public signature, error field, and required derive exactly; returned cursors are absolute indices.

2. **R4–R6:** Encode seven-bit groups least significant first, with continuation set only when another group follows. Encoding must be minimal: zero is `[0]`; `u64::MAX` is nine `0xff` bytes followed by `0x01`.

3. **R7–R8, R15–R16:** Validate `start <= input.len()` first, including for a zero-count batch. An invalid start returns `StartOutOfBounds { offset: start }`; equality is valid, yielding truncation for one integer but an unchanged cursor and empty vector for count zero.

4. **R9–R10, R18:** Stop immediately at the first clear continuation bit; trailing bytes cannot affect that result. Missing bytes before termination yield `Truncated { offset: input.len(), start }`, retaining the individual integer’s initial cursor.

5. **R11–R12:** Inspect the tenth byte before accepting termination: payload greater than one **or** any set continuation bit means overflow at that byte. Thus `0x02`, `0x80`, and `0x81` all overflow there; overflow wins over end-of-input truncation, and an eleventh byte is never inspected.

6. **R6, R10, R13:** Nonminimal encodings are valid through ten bytes, including nine `0x80` bytes followed by `0x00`. One through nine continuation-only bytes ending at EOF are truncated; a tenth continuation byte is overflow. Avoid shifts outside the `u64` width.

7. **R14, R17–R18:** Decode exactly `count` values in encounter order, ignoring everything afterward. On failure, return the error unchanged with that integer’s start and no partial vector. Huge counts must not themselves cause capacity/arithmetic panics; a short input should reach its decoding error.

8. **R19–R21:** Signed APIs apply zigzag to the full 64-bit domain without signed overflow, including avoiding `abs(i64::MIN)`. Check both extrema; decoding inherits all unsigned errors, cursor behavior, and overlong acceptance before applying the inverse mapping.

9. **R22–R25:** Expose all six stream methods with the specified signatures. New state is `(position, pending_len) = (0, 0)`; successful pushes count every byte, including unfinished bytes. Emit each value only in the chunk that terminates it, then reset the integer’s group counter.

10. **R25–R26, R29:** Empty pushes succeed without any change, even with pending data. Incomplete chunks are buffered without truncation. Apply the same tenth-byte overflow rules across chunk boundaries, using absolute offsets and the integer’s original start; position arithmetic must remain safe within the stated `usize` limit.

11. **R27:** Any overflow rolls back the entire current push: position, pending bytes/value/group count, and completed values earlier in that chunk. Preserve prior successful pushes exactly, so retrying a corrected chunk starts from the state before the failed push.

12. **R28–R29:** `finish` reports truncation precisely at `position()` with start `position() - pending_len()`, without changing or sealing state; repeated calls agree, and later pushes can complete it. `reset` clears all state, including pending accumulation, and restarts absolute positions at zero.
