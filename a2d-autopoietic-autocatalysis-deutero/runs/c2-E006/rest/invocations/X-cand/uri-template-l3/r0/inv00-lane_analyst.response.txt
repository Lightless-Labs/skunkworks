1. **R1–R2:** Use one std-only Rust 2024 source file, the exact public enum variants and function signature, and all four required derives. No `main` is required; no inner attributes or inner doc comments are allowed.

2. **R3–R4:** Preserve literals byte for byte; an empty template returns `Ok("")`. All error positions count UTF-8 bytes from the template’s beginning, not characters or expression-relative offsets.

3. **R5, R21:** Validate the entire template before binding lookup or expansion. The first syntax error in left-to-right scanning wins; missing bindings and arbitrary scalar values never cause errors.

4. **R6–R7:** For each opening brace, first locate the first following closing brace. If absent, report `Unclosed` at the opening, even with inner openings. If present, report the first inner opening as `NestedOpen` before any content checks. An outside `}` is `UnexpectedClose`; doubled braces are not escapes.

5. **R8, R11:** Recognize at most one leading operator, before specifier validation. All seven recognized operators are supported, so no input triggers `UnsupportedOperator` under this specification. Other punctuation, including a second operator character, undergoes name validation.

6. **R9:** Both `{}` and an operator-only expression produce `EmptyExpression` at the closing brace. Otherwise preserve every comma-separated empty entry: its `EmptyVariable` position is immediately after the preceding comma, or the content start for a leading empty entry.

7. **R10–R11:** Names require an ASCII letter or underscore first, then ASCII letters, digits, or underscores. Report the first offending byte; do not trim whitespace or accept modifiers. Validate each specifier’s name before checking its duplicate status, then advance to the next specifier.

8. **R4, R11–R12:** Duplicate detection is case sensitive and confined to one expression, with the error at the repeated specifier’s start. Binding duplicates are allowed: exact-name lookup uses the last binding, even if empty. Ignore unused or invalidly named bindings.

9. **R13–R14:** Encode UTF-8 bytes separately with uppercase `%HH`. Greedily preserve existing `%` plus two ASCII hex digits, uppercasing those digits without decoding—even `%41` and `%25`. For malformed triplets, encode only the percent first and continue processing the remaining bytes normally.

10. **R12, R15–R18:** Missing variables contribute neither fields nor separators; present empty values contribute empty fields. Simple and `+` join with commas without a prefix; `#`, `.`, and `/` emit their prefix whenever any field exists, including an empty one. Zero fields emit nothing.

11. **R13, R16–R18:** Only `+` and `#` preserve the exact listed reserved ASCII characters in addition to unreserved characters. Other operators encode reserved characters; spaces always become `%20`, and percent handling always follows R14.

12. **R17, R19–R21:** `;` emits `;name` for an empty value and `;name=value` otherwise; `?` and `&` retain `name=` for empty values. Preserve specifier order and emit each expression’s prefix independently, without examining prior output. Malformed input must return errors without panics; calls must neither mutate inputs nor share state.
