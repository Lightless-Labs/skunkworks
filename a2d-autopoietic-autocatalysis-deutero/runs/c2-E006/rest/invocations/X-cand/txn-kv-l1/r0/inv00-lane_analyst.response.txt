1. **R1–R2:** Deliver one std-only source file in `rust` fences, compiling with edition 2024; no inner attributes/docs. Preserve every signature, public API item, field and variant, and required derives exactly.

2. **R2, R13:** Only the empty key is invalid; Unicode, whitespace and punctuation are allowed. get/set/delete must return `KeyEmpty` before accessing data. Empty values and count arguments are valid; compare strings exactly using Rust ordering, without normalization.

3. **R3–R5:** Every data operation uses the innermost map, or committed data at depth zero, including prior writes/deletes. Missing nonempty keys yield `get → None`, `delete → false`; get returns an owned string.

4. **R4–R5:** set overwrites one key; delete returns true exactly when that key existed. count counts matching keys using whole-value equality, including empty values; an empty map yields zero. Return `usize` without narrowing or wrapping intermediate counters.

5. **R6:** begin copies the currently visible map. Depths zero through four are valid; beginning at depth three succeeds, while beginning at four returns `DepthLimit` and leaves depth and maps unchanged.

6. **R7:** commit at depth zero returns `NoTransaction`. Otherwise pop exactly one scope and replace its parent’s entire map, preserving deletions too. An inner commit remains reversible by an outer rollback.

7. **R8:** rollback at depth zero returns `NoTransaction`; otherwise discard exactly one scope and expose its unchanged parent. Neither rollback nor commit reverts the snapshot registry.

8. **R9, R15:** snapshot captures the complete visible map, including an empty map, without recording depth or scopes. Replacement fully overwrites the saved map; saved data survives transactions and remains independent of later edits.

9. **R10, R15:** restore replaces the entire visible map with a copy, removing keys absent from the snapshot. It preserves depth, suspended parent maps and the snapshot; normal subsequent commit/rollback semantics apply.

10. **R11–R12:** For all three snapshot operations, check `NameEmpty` first, then validate left to right before lookup or capacity checks. The first character must be ASCII lowercase; later characters allow only ASCII lowercase, digits or underscores. Report the first invalid character’s UTF-8 **byte offset**.

11. **R11–R12, R16:** Unknown valid restore/forget names return `SnapshotMissing` containing the exact input. Only creating a fourth distinct valid snapshot returns `SnapshotLimit`; replacing at three succeeds. Successful forget frees a slot and changes no data or scopes.

12. **R14–R16:** Every returned error preserves all data, scopes and snapshots. Stores share no state; snapshot slots survive rollback. All operations are deterministic, with no automatic commit, expiry, normalization, persistence or concurrency behavior.
