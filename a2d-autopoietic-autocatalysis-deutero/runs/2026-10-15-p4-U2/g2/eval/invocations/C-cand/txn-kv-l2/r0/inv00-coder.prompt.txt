R3. A visible map consists of committed data at depth zero, otherwise the innermost working scope. Every get/count/snapshot uses that map, including earlier writes and deletes in the same scope. get returns an owned value or None, never an error for a missing nonempty key.
R4. set inserts or overwrites one key; delete removes it and returns true exactly when it was present in the visible map. Deleting a missing nonempty key returns false. Both operate only on the visible map.
R5. count returns the number of visible keys whose entire value equals the supplied string; it counts keys, not distinct values. Empty values are included. An empty store has count zero.
R6. begin copies the visible map into a new working scope. At most four scopes may be open; a fifth begin returns DepthLimit without adding a scope. depth returns the number of open scopes.
R7. commit without a scope returns NoTransaction. Otherwise it removes the innermost scope and replaces its parent working map, or committed map at depth zero, with the removed scope's complete map. Inner commit is still undone by a later outer rollback.
R8. rollback without a scope returns NoTransaction. Otherwise it discards exactly the innermost scope; the parent map becomes visible again. It does not undo changes to the snapshot registry.
R9. snapshot(name) copies the complete visible map into a registry under name, replacing an existing entry of the same name. A snapshot never records the scope stack or depth. Snapshots can be taken and replaced inside scopes.
R10. restore(name) replaces only the visible map with a copy of the named snapshot. Scope depth and suspended parent maps are unchanged. Restoring inside a scope can subsequently be committed or rolled back normally.
R11. forget(name) removes the named snapshot and never changes data or scopes. restore and forget of an unknown valid name return SnapshotMissing(name.to_string()).
R12. snapshot/restore/forget with an empty name return NameEmpty, before any registry lookup or mutation. Valid names are compared exactly.
R13. get/set/delete with an empty key return KeyEmpty before any data access or mutation. count's argument is a value, so an empty argument is valid.
R14. At level 1 every error leaves all data, scopes and snapshots unchanged. Independent Store instances share no state.

R21. begin copies only currently live entries with their existing absolute deadlines; it never restarts TTL. commit preserves deadlines when replacing its parent map.
R22. rollback exposes the suspended parent map and immediately purges it at the admitted now. Thus a discarded overwrite cannot resurrect an original value whose original deadline has passed. Values whose original deadline is still in the future are restored with that original deadline.
